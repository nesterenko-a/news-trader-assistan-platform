# 24. Реальное время — актуальные цены и показатели рынка (ТЗ и дизайн)

**Статус:** реализовано v1.3 (live-котировки по SSE на всех страницах с ценами + **live-обновление OI фьючерсов** (`event: oi`) на карточке и `/indicators`; демон `realtime_updater`; см. обновления в 10/13/14/12/17)
**Система:** NewsTrader Assistant
**Приоритет задачи:** этап 2 дорожной карты (12-roadmap.md), «Углубление аналитики» — актуальность рыночных данных
**Связанные документы:** [10-api-specification.md](./10-api-specification.md), [13-operations.md](./13-operations.md), [14-web-interface.md](./14-web-interface.md), [16-working-process.md](./16-working-process.md), [17-quickstart.md](./17-quickstart.md), [12-roadmap.md](./12-roadmap.md), [19-market-indicators.md](./19-market-indicators.md)

## 1. Обоснование и цели

Текущая система обновляет рыночные данные **пакетно**: дневные свечи — в Ежедневном конвейере (`daily_pipeline`, фаза 2) и `update_prices`; открытые позиции фьючерсов (OI) — `update_oi`; текущая котировка (`LAST`) — **на лету** из MOEX ISS при каждом обращении к карточке/портфелю (`fetch_quote`), без кэша и стриминга. Индикаторы (RSI, MACD, Volume Profile и др.) пересчитываются on-the-fly из сохранённых свечей при обращении.

**Проблема:** владелец системы (администратор) хочет, чтобы цены акций и фьючерсов и связанные показатели всегда были актуальными, а пользователи веб-интерфейса видели живую котировку на карточке бумаги без ручного перезапуска конвейера и без перезагрузки страницы.

**Цель:** автономный демон, который в фоне периодически обновляет актуальные цены, свечи и OI по настраиваемому составу инструментов; веб-интерфейс транслирует живые котировки пользователям по **SSE (Server-Sent Events)**.

**Не-цели:**
- Не собираются новости и не анализируются тексты (LLM) — эти показатели остаются в конвейере [`08-analysis-pipeline.md`](./08-analysis-pipeline.md).
- Не выполняются сделки и не изменяются стратегии/вердикты.
- Не хранится истории внутридневных (минутных) свечей — в реалтайме обновляется текущая котировка (последняя цена/OHLC дня) и дневные свечи; внутридневные бары — отдельная задача (см. 23 §12).
- Индикаторы не пересчитываются циклически — они считаются on-the-fly из актуальных свечей при обращении (детерминизм, см. 19).

## 2. Термины

| Термин | Значение |
|---|---|
| **Realtime-демон** | Автономный `asyncio`-процесс (`scripts/realtime_updater.py`), который периодически опрашивает MOEX ISS и пишет актуальные значения в БД |
| **Live-котировка** | Текущая котировка в `real_time_quotes`: последняя цена (LAST), OHLC дня, объём, метка времени |
| **SSE (Server-Sent Events)** | Односторонний стрим по HTTP: сервер → браузер, авто-реконнект. Ведёт к обновлению цены на карточке без перезагрузки |
| **Показатели из БД** | Свечи (`market_candles`), открытые позиции (`market_open_positions`, `market_open_position_client_groups`), live-котировки (`real_time_quotes`) |
| **Шаблон фьючерсов** | Существующая сущность `FuturesTemplate` (таблица `futures_templates`, страница `/admin/futures-templates`) — список SECID для отслеживания OI |

## 3. Пользовательские сценарии (UC)

- **UC-01 (администратор). Настройка realtime.** Администратор открывает админ-панель, видит блок «Реальное время»: тумблер «включить актуализацию», интервалы обновления (котировки / свечи / OI), выбор шаблона фьючерсов. Изменяет и сохраняет.
- **UC-02 (администратор). Управление демоном.** Администратор запускает/останавливает скрипт-демон из админ-панели (как прочие скрипты `SCRIPTS`); видит последний запуск и вывод.
- **UC-03 (пользователь). Живая котировка.** На карточке бумаги цена и котировки обновляются автоматически через SSE в течение торговой сессии без перезагрузки страницы. Демон при этом может не работать — SSE отдаёт последние известные значения из БД.
- **UC-04.** После закрытия торговой сессии демон доформирует и пишет финальные дневные свечи и OI, чтобы индикаторы/стратегии/бэктест за следующий прогон использовали актуальные данные.

## 5. Состав инструментов (scope)

- **Акции:** объединение множеств тикеров из `watchlist` всех пользователей (таблица `watchlist_items` → `Security`) и `MVP_TICKERS` (настройка `mvp_tickers`). Дедупликация по `security_id`.
- **Фьючерсы:** SECID из **выбранного шаблона** `FuturesTemplate` (указывается в `realtime_config.futures_template_id`). Если шаблон не выбран — фьючерсы не обновляются (O-фазы в этом случае пропускаются).
- Состав вычисляется демоном **на каждой итерации** при запросе новых котировок/свечей — чтобы подхватывать новые watchlist без перезапуска.

## 6. Модель данных (миграция Liquibase)

Схема управляется миграциями (правило 6/16 §6). Новый ченджлог **`liquibase/changelogs/026_market_realtime.xml`**, включается в `changelog-master.xml` (следующий после 025).

### 6.1. Таблица `realtime_config` (singleton-настройки; одна строка)

| Колонка | Тип | Назначение |
|---|---|---|
| `id` | INTEGER PK autoincrement | Идентификатор (всегда одна строка) |
| `enabled` | BOOLEAN default false | Мастер-тумблер «включить актуализацию» |
| `interval_quotes_sec` | INTEGER default 60 | Интервал обновления live-котировок (сек) |
| `interval_candles_sec` | INTEGER default 300 | Интервал доформирования дневных свечей (сек) |
| `interval_oi_sec` | INTEGER default 900 | Интервал обновления OI фьючерсов (сек) |
| `futures_template_id` | INTEGER nullable FK → futures_templates.id | Шаблон фьючерсов для OI/свечей фьючерсов |
| `updated_at` | TIMESTAMP | Время последнего сохранения настроек |

Singleton-строка создаётся при `seed_db` (или демоном при первом чтении, если отсутствует).

### 6.2. Таблица `real_time_quotes` (live-котировки)

| Колонка | Тип | Назначение |
|---|---|---|
| `security_id` | INTEGER PK FK → securities.id | Бумага |
| `last` | FLOAT nullable | Последняя цена (LAST) |
| `open` | FLOAT nullable | Цена открытия дня |
| `high` | FLOAT nullable | Максимум дня |
| `low` | FLOAT nullable | Минимум дня |
| `volume` | BIGINT default 0 | Объём дня |
| `updated_at` | TIMESTAMP | Время обновления |

Запись одна на бумагу (upsert). При отсутствии данных MOEX — метка не обновляется либо значение `last=NULL` (предыдущее остаётся).

## 7. API (REST, версия `/v1`)

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/v1/realtime/stream?tickers=AFLT,SBER,...` | **SSE-стрим.** Требует аутентификацию. Периодически (например, раз в 5–10 с) читает `real_time_quotes` по переданным тикерам и шлёт события. Формат события (по каждому тикеру): `event: quote`, `data: {"ticker":"AFLT","last":123.0,"open":..., "high":..., "low":..., "volume":..., "ts":"ISO-UTC"}`. Если по тикеру нет записи — событие не шлётся. Комментарий `: keep-alive` для поддержания соединения |

- Реализация с использованием `StreamingResponse`/`EventSourceResponse` (Starlette/`sse-starlette` при необходимости). В заголовках — `Cache-Control: no-cache`, `Content-Type: text/event-stream`, `Connection: keep-alive`.
- Аутентификация: cookie `nt_token` или `Authorization: Bearer` (как прочие `/v1` приватные эндпоинты).

## 9. Скрипт-демон — реализация (`scripts/realtime_updater.py`)

```
скрипт-демон (запуск из админки как SCRIPTS или .bat)
   │
   ▼
init_db() + чтение realtime_config
   │
   ├─ если !enabled → печать «Realtime отключён», выход (код 0)
   │
   └─ если enabled → бесконечный цикл:
        ├─ котировки  (каждый interval_quotes_sec):
        │      состав = акции(watchlist+mvp) + фьючерсы(шаблон)
        │      для каждого: fetch_quote → upsert в real_time_quotes
        ├─ свечи     (каждый interval_candles_sec):
        │      sync_security_prices по акциям и фьючерсам шаблона
        ├─ OI        (каждый interval_oi_sec):
        │      sync_security_oi по шаблону (вкл. группы клиентов)
        └─ sleep(минимальный интервал)
```

- Детали:
  - Настройки перечитываются **каждую итерацию** — изменение тумблера/интервалов в админке применяется без перезапуска (если демон жив).
  - Торговый календарь: если нет свежих свечей за день и биржа закрыта/сессия не началась — запросы котировок можно делать, но MOEX вернёт LAST=None; демон просто не перезаписывает `last=NULL`, а хранит последнее значение.
  - Таймауты и повторные попытки — переиспользование retry-логики `MOEXClient.fetch_candles` (паттерн 302/429/5xx + сетевые сбои).
  - При недоступности MOEX (повторные сбои) — `app.notices.service.add_notice(source="realtime_moex")` (`warning`), при восстановлении — снятие уведомления.
  - Завершение по Ctrl+C/SIGTERM — корректный выход.
- Переиспользуются: `sync_security_prices` (`app/market/prices.py`), `sync_security_oi` и `ensure_futures_security` (`app/market/oi_data.py`), `MOEXClient.fetch_quote` (`app/market/moex.py`), `get_settings`/`mvp_tickers` (`app/config.py`).

## 11. SSE — клиентская перерисовка (все страницы с ценами)

- **Карточка бумаги** `/securities/{ticker}` (акции/фьючерсы): JS открывает `EventSource('/v1/realtime/stream?tickers=<ticker>')` и обновляет блок Цена/Макс-мин/Объём.
- **Другие страницы с ценами** (портфель `/portfolio`, виртуальный портфель `/paper`, «Лучшие возможности» `/top5`): общий JS-helper `initRealtimeQuotes` в `/static/app.js` (подключается глобально в `base.html`) собирает тикеры страницы из разметки `data-rt-*` и подписывается на **один SSE-стрим** по набору тикеров; при `event: quote` обновляет ячейки цены и **пересчитывает производные** (стоимость, P&L, P&L%, итоги — для портфеля и paper).
- **OI фьючерсов (live)**: SSE-стрим дополнительно испускает `event: oi` (последний `open_position`, изменение к предыдущему дню, группы клиентов физ/юр — из `market_open_positions`, которую обновляет демон). JS-helper обновляет разметку `[data-rt-oi-value]`/`[data-rt-oi-change]`/`[data-rt-oi-groups]`. Выведено live на карточке фьючерса (`/securities/{ticker}`, блок «Открытый интерес») и на вкладке `/indicators` OI (строка «Текущий OI / ΔOI»).
- При `event: quote` обновляет значения в DOM (последняя цена и, при наличии, OHLC/объём) без перезагрузки страницы.
- При закрытии страницы / размонтировании — `EventSource.close()`.
- Если эндпоинт вернул ошибку доступа (не авторизован) — корректная обработка (котировки не обновляются, страница не падает).
- Индикаторы пересчитываются на лету движком при обращении из актуальных свечей — отдельного их обновления по SSE не производится (см. не-цели).

Разметка для live-обновления: ячейка цены — `[data-rt-price="TICKER"]`; строка с пересчётом P&L — `tr[data-rt-recalc="TICKER"][data-rq][data-cost]` с ячейками `[data-rt-field="cost|pnl|pnlpct"]` и итогами `[data-rt-total="value|pnl"]`.

## 12. Безопасность и правовые аспекты

- SSE-эндпоинт требует аутентификации (как прочие приватные функции; FR-24-09). Данные live-котировок — публичные (MOEX), но доступ к эндпоинту — авторизованный.
- Демон не обрабатывает пользовательский ввод вне админки; интервалы/шаблон — только `admin`-роль.
- Нет новых секретов; сохраняется работа с открытыми данными MOEX ISS (см. 11-security-compliance.md).

## 13. Ограничения и не-скоуп (первая версия)

- **Не** транслируется полноценный «стакан»/тики — только last/OHLC/объём дня.
- **Нет** актуализации новостей/LLM — остаётся в конвейере.
- **Нет** внутридневных (минутных) свечей и их истории.
- Статус демона — последний запуск из `script_runs`; активный heartbeat-probe (в отличие от монитора) — отдельная задача.
- Состав инструментов пересчитывается демоном на каждой итерации (watchlist всех пользователей) — на большом объёме watchlist может возрасти число запросов к MOEX; при необходимости добавить кэш/дедупликацию (на будущее).

- [x] Демон записывает live-котировки (upsert в `real_time_quotes` через `fetch_scope_quotes`/`upsert_quote`; unit-покрытие; против реального MOEX — требует внешнего окружения, см. Notes).
- [x] Демон доформировывает дневные свечи акций/фьючерсов и OI (вкл. группы клиентов) по шаблону (переиспользует `sync_security_prices`/`sync_security_oi`).
- [x] В админке тумблер/интервалы/шаблон сохраняются (`POST /admin/realtime/save`, unit-тест), применяются без перезапуска демона (настройки перечитываются каждую итерацию).
- [x] `GET /v1/realtime/stream?tickers=...` отдаёт SSE-событие `quote` с актуальными значениями (unit-проверка `_quote_event`); без авторизации возвращает 401 (`get_current_user`).
- [x] На карточке бумаги котировки обновляются по SSE без перезагрузки; при недоступности демона/пустых данных страница не падает (JS закрывает EventSource на ошибку).
- [x] `compileall`, `pytest -q` проходят (unit в `tests/test_realtime.py`); `npx playwright test`/`smoke` — по регламенту при UI-изменениях (реестр e2e — docs/21).
- [x] Документация обновлена, версии затронутых документов подняты (10→1.25, 13→1.56, 14→1.78, 12→1.54, 24→реализовано, README), roadmap обновлён.
