# 08. Конвейер анализа новостей

**Статус:** утверждено v1.0  
**Система:** NewsTrader Assistant

Документ описывает, как новость проходит путь от источника до структурированного артефакта анализа, пригодного для движка стратегий ([09-strategy-engine.md](./09-strategy-engine.md)).

## 1. Этапы конвейера

```
[1] Сбор     → [2] Нормализация → [3] Дедупликация → [4] Извлечение
                                                        сущностей и фактов
                                                        │
[7] Индексация ← [6] Расчёт значимости ← [5] Тональность
    и хранение      (impact score)          и тематика
```

### 1.1. Сбор

- Коннекторы опрашивают источники по расписанию или получают события по вебхукам.
- Разные источники обрабатываются независимо; сбой одного не блокирует другие.
- Каждое событие попадает в очередь для дальнейшей обработки.

### 1.2. Нормализация

- Очистка от HTML-разметки, рекламы, шаблонных блоков.
- Приведение к единой схеме: заголовок, текст, дата публикации, язык, автор.
- Определение языка (для выбора моделей анализа).
- Разрешение относительных дат («вчера», «час назад») в абсолютные с учётом часового пояса источника.

### 1.3. Дедупликация

- Кандидаты на дубликат находятся по сигнатурам: хеш заголовка, хеш текста, URL-нормализация.
- Семантическая кластеризация: перефразированные перепечатки одной новости попадают в один кластер.
- Правила:
  - канонический текст — из наиболее авторитетного источника кластера;
  - список источников кластера сохраняется (для статистики распространённости новости);
  - дубликаты не анализируются повторно (экономия ресурсов).

### 1.4. Извлечение сущностей и фактов

- Сопоставление текста со словарём сущностей графа (по имени и алиасам) + модель распознавания имён (NER).
- Новые неизвестные имена могут предлагаться как кандидаты в сущности (куратор решает, добавлять ли в граф).
- Извлечение фактов: числа и их контекст (ставка 6,5%, рост 12%, прогноз прибыли, цена нефти $90).
- Разрешение упоминаний: «Аэрофлот» и «AFLT» → одна сущность.

### 1.5. Тональность и тематика

- Тональность вычисляется **по каждой сущности отдельно**, а не только по тексту в целом. Новость «банк зафиксировал убыток, но увеличил дивиденды» — негатив по прибыли и позитив по дивидендам.
- Тематика классифицируется: макроэкономика, отрасль, компания, геополитика, регуляторика, техника/события.
- При недостаточной уверенности модели результат помечается «low confidence» и учитывается с малым весом.

### 1.6. Расчёт значимости (impact score)

Значимость новости для сущности зависит от:

| Фактор | Влияние |
|---|---|
| Тональность (не нейтральность) | сильная тональность → выше значимость |
| Роль сущности (primary/secondary) | главная сущность → выше |
| Авторитет источника | авторитетный → выше |
| Количество источников в кластере | много перепечаток → новость «расходится» → выше |
| Релевантность тематики рынку | макро/отраслевая → шире влияние |
| Свежесть (temporal decay) | новость «затухает» по экспоненте: `w(t) = e^(−λ·(t_now − t_pub))` |

Итоговая значимость: **impact = base_impact × source_weight × cluster_weight × decay(t)**.

### 1.7. Индексация и хранение

- Сохранение всех артефактов анализа (Article, ArticleEntity) с привязкой к версии моделей.
- Полнотекстовый индекс для поиска и фильтров.
- Событие «новость обработана» публикуется для потребителей: движка стратегий, алертинга.

## 2. Связь с knowledge graph

- Извлечённые сущности связываются с узлами графа.
- Для каждой пары «сущность из статьи — целевая бумага» движок строит цепочки влияния через рёбра графа.
- Если в тексте обнаруживается устойчивая новая зависимость («рост ставки → давление на ипотечные банки»), она может быть предложена как кандидат в рёбра графа (FR-03-04).

## 3. Контроль качества

- Валидационный набор размеченных новостей для метрик (NFR-04-01, NFR-04-02).
- A/B-прогон новых версий моделей перед продом.
- При ошибках анализа (сбой модели, нет данных) новость помечается и не влияет на вердикты, пока не обработана корректно.

## 4. Производительность

- Конвейер асинхронный: очередь сглаживает пики (например, день отчётностей).
- Тяжёлые модели анализа выносятся в отдельные воркеры, масштабируются горизонтально.
- Кэширование повторной обработки одинаковых текстов.
