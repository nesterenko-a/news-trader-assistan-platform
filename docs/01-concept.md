# 01. Концепция системы

**Статус:** утверждено v1.0  
**Система:** NewsTrader Assistant  
**Авторы:** аналитическая группа проекта NewsTraderBot

## 1. Общее описание

**NewsTrader Assistant** — интеллектуальный ассистент для торговли ценными бумагами. Система формирует аналитику и стратегии покупки/продажи по конкретной ценной бумаге на основе:

- новостей и статей из открытых источников;
- анализа тональности и смысла текстов;
- учёта взаимосвязей между отраслями экономики (девальвация валюты, цены на нефть, ключевые ставки, инфляция и т.д.);
- биржевых индикаторов и рыночных данных.

Ключевое отличие от простых новостных агрегаторов — **понимание причинно-следственных связей экономики**. Система не просто показывает «новость про нефть вышла», а объясняет: рост нефти → дорожает топливо → растут издержки авиакомпаний → акции авиаперевозчиков под давлением → при этом нефтяные компании в плюсе → рост цен на топливо усиливает инфляцию → регулятор может поднять ставку → фондовый рынок в целом под давлением.

## 2. Решаемая проблема

Частному инвестору сложно:

1. Обрабатывать большой поток новостей и выделять действительно значимые события.
2. Понимать, **как** новость влияет на конкретную бумагу (прямое влияние → косвенное → отраслевое → макроэкономическое).
3. Сопоставлять разрозненные данные: новости, котировки, макроэкономику, отчёты компаний.
4. Получать **обоснованный** вывод со ссылками на первоисточники, а не голословный совет.
5. Действовать быстро: свежие новости теряют ценность с каждым часом.

**NewsTrader Assistant** снимает эти барьеры: пользователь задаёт вопрос о бумаге и получает структурированный ответ-стратегию с цепочкой обоснований.

## 3. Цели системы

1. Собирать и нормализовать новости и статьи из множества источников.
2. Анализировать тексты: тематика, тональность, вовлечённые сущности, временной контекст.
3. Моделировать взаимосвязи отраслей экономики и оценивать **косвенные** эффекты новостей.
4. Оценивать суммарное влияние событий на конкретную ценную бумагу.
5. Формировать стратегию: **ПОКУПКА / ПРОДАЖА / УДЕРЖАНИЕ** с горизонтом, целевыми ценами и уровнем уверенности.
6. Обосновывать каждое решение: цитаты, ссылки, научные источники, биржевые индикаторы, альтернативные точки зрения.
7. Обеспечивать прозрачность: пользователь видит «путь рассуждения» системы, а не чёрный ящик.

## 4. Не-цели (границы системы)

Система **не является**:

- гарантией прибыли или «граалью» — это аналитический инструмент, а не предсказатель будущего;
- высокочастотным трейдером (HFT) — задержки в минуты, не миллисекунды;
- полноценной торговой платформой — исполнение сделок вне рамок текущей версии;
- источником «инсайдерской» информации — работаем только с открытыми данными;
- заменой персональному финансовому консультанту — рекомендации носят информационный характер.

## 5. Целевые пользователи

| Роль | Потребности |
|---|---|
| Частный инвестор | Понять перспективы бумаги, получить стратегию с обоснованием, сэкономить время |
| Трейдер среднесрочной торговли | Отслеживать события и их влияние на портфель, получать алерты |
| Аналитик | Быстрый сбор и структуризация информации по сектору/бумаге |
| Разработчик/исследователь | Использовать API и данные системы для собственных моделей |

## 6. Основные функции

Приоритеты: **P0** — ядро без которого система не работает, **P1** — критично для полноценного продукта, **P2** — расширение возможностей.

### 6.1. Сбор и нормализация данных (P0)
- Подключение множества источников: новостные агентства, RSS-ленты, сайты компаний, Telegram-каналы, регуляторы.
- Нормализация текста: извлечение дат, авторов, языка, дедупликация (похожие перепечатки).
- Каталогизация источников с оценкой достоверности и репутации.

### 6.2. Анализ текстов (P0)
- Определение тематики (макроэкономика, компания, отрасль, геополитика, регуляторика и т.д.).
- Тональность: позитив/негатив/нейтрально по отношению к вовлечённым сущностям.
- Извлечение сущностей: компании, тикеры, валюты, сырьё, индексы, персоны, события.
- Извлечение ключевых фактов и чисел (прибыль, ставка, цена, прогноз).

### 6.3. Модель взаимосвязей экономики — knowledge graph (P0)
- Граф сущностей: компании, отрасли, сырьевые товары, валюты, индексы, макроиндикаторы, регионы, регуляторы.
- Рёбра-влияния: направление (+ / −), сила (слабое/среднее/сильное), характер (прямое/косвенное), уверенность.
- Примеры связей:
  - девальвация валюты → рост акций экспортёров, падение импортёров, рост инфляции;
  - рост нефти → рост нефтегазового сектора, давление на авиацию и логистику, рост инфляции;
  - повышение ключевой ставки → давление на growth-акции, поддержка банков, рост доходности облигаций;
  - сильный PMI → поддержка циклических секторов;
  - геополитические события → рост оборонки, волатильность валют и сырья.
- Механизм **вывода**: из события по одной сущности система вычисляет цепочку последствий для других сущностей и бумаг.

### 6.4. Оценка влияния на ценную бумагу (P0)
- Агрегация прямых и косвенных эффектов в сводный «сигнал» по бумаге.
- Учёт **временного затухания**: свежая новость важнее новости недельной давности.
- Сопоставление новостного сигнала с ценой и биржевыми индикаторами.

### 6.5. Биржевые индикаторы (P0)
- Котировки, объёмы, волатильность.
- Технические индикаторы: RSI, MACD, скользящие средние, уровни поддержки/сопротивления.
- Макроэкономический календарь: заседания ЦБ, публикация CPI/PMI/ВВП, сезоны отчётностей.

### 6.6. Генерация стратегии с обоснованием (P0)
- Вердикт: **ПОКУПКА / ПРОДАЖА / УДЕРЖАНИЕ**.
- Горизонт: краткосрочный / среднесрочный / долгосрочный.
- Целевые уровни: цена входа, take-profit, stop-loss (справочно).
- Уровень уверенности и факторов, которые могут его изменить.
- **Обоснование**: цепочка «новость → связь → эффект на бумагу», цитаты, ссылки, научные работы, показатели.
- **Альтернативная точка зрения**: контраргументы и риски, которые противоречат вердикту.

### 6.7. Работа с пользователем (P0)
- Запрос аналитики по бумаге (тикер или название).
- Список отслеживаемых бумаг (watchlist) и портфель.
- Лента новостей по выбранной бумаге с пометками о влиянии.
- История запросов и предыдущих стратегий.

### 6.8. Алерты и уведомления (P1)
- Уведомление при появлении новости с высокой значимостью по отслеживаемой бумаге.
- Настраиваемые пороги значимости и тональности.

### 6.9. Обучение и обратная связь (P1)
- Пользователь оценивает рекомендации («сработало / не сработало»).
- Система собирает статистику качества и корректирует веса факторов.

### 6.10. Бэктестинг и песочница (P1)
- Проверка стратегий на исторических данных.
- «Бумажный режим»: имитация портфеля без реальных сделок.
- Отчёт «как бы сработал вердикт за последние N месяцев».

### 6.11. Расширенные источники (P2)
- Мультиязычность: русский, английский и другие языки источников.
- Поиск научных публикаций и аналитических отчётов.
- Видео/подкасты с транскрибацией (дальний горизонт).

## 7. Сценарий работы «с высоты птичьего полёта»

```
Пользователь: «Что с акциями Авиакомпании X?»

1. Система находит свежие новости по авиакомпании и отрасли.
2. Находит новости-факторы: «Нефть выросла на 8% за неделю».
3. Граф связей: нефть → топливо → издержки авиакомпаний → маржинальность ↓.
4. Тональность новостей по самой авиакомпании — в основном нейтральная.
5. Индикаторы: RSI на уровне 32, цена у нижней границы канала.
6. Вердикт: ПРОДАЖА (среднесрочно), уверенность — средняя.
7. Обоснование: цитата из новости про нефть + ссылка; объяснение цепочки влияния;
   контраргумент: «если авиакомпания застраховала топливо на квартал вперёд — эффект слабее».
8. Пользователь видит: вердикт, цепочку, источники, риски, индикаторы.
```

## 8. Принципы проектирования

1. **Прозрачность** — каждое утверждение системы имеет источник или логическую цепочку.
2. **Независимость от технологий** — архитектура описывается на уровне компонентов, а не конкретных библиотек.
3. **Модульность** — сборка, анализ, граф, стратегия — отдельные компоненты с чёткими интерфейсами.
4. **Обучаемость** — система накапливает опыт и уточняет собственные модели.
5. **Консервативность выводов** — при недостатке данных система говорит «недостаточно информации» вместо выдумывания вердикта.
6. **Ответственность** — система явно сообщает о рисках и не выдаёт советы без оговорок (см. 11-security-compliance.md).

## 9. Принятые решения (MVP)

- **Технологический стек:** Python + FastAPI, PostgreSQL; knowledge graph — таблицы в PostgreSQL с обходом цепочек в коде; NLP — через LLM API (стартовый провайдер DeepSeek, предусмотрена смена на OpenAI).
- **Рынок:** Мосбиржа (MOEX ISS API). Первый вертикальный срез — авиация + нефть (AFLT, LKOH, GAZP и связанные бумаги).
- **Источники новостей:** RSS российских агентств (РБК, Интерфакс, ТАСС и др.) + Telegram-каналы.
- **Каналы доступа:** REST API, минимальный веб-интерфейс, Telegram-бот.
- **Глубина графа:** на старте ~50–100 сущностей и курируемых связей по срезанным отраслям.
- **Научные ссылки:** на этапе MVP используются при наличии в текстах источников; автоматический поиск — на этапе 2.
