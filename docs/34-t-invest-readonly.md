# 34. Подключение Т-Инвестиций: портфель только для чтения

**Статус:** проект v1.0, ожидает согласования дизайна
**Система:** NewsTrader Assistant
**Приоритет:** первый срез брокерских интеграций; направление согласовано пользователем.

## 1. Цель и границы

Подключить реальный счёт Т-Инвестиций и показывать его портфель в NewsTrader Assistant. Первый срез: один токен и один выбранный счёт на пользователя, список доступных счетов, ручное обновление, позиции и оценка брокера, переход к локальной аналитике при надёжном сопоставлении инструмента.

Существующий ручной портфель и paper trading сохраняют свои данные и назначение. Брокерские позиции хранятся отдельно. Торговые поручения, переводы, MCP, отправка портфеля внешним LLM, история операций и постоянные стримы — последующие отдельные срезы.

## 2. Проверенные возможности и источники

Исследование выполнено 12.10.2026 по официальной документации:

- [T-Invest API](https://developer.tbank.ru/invest/intro/intro/) — счета, портфель, рыночные данные; Python SDK.
- [Токены](https://developer.tbank.ru/invest/intro/intro/token) — read-only не разрешает торговые поручения; доступ можно ограничить конкретным счётом. Пользователь выпускает токен на сайте банка.
- [Сервис портфеля](https://developer.tbank.ru/invest/services/operations/head-operations) — GetPortfolio предоставляет оценку и доходность; GetPositions — позиции и заблокированные средства. У инструментов есть особенности единиц, валют и оценки; портфель Инвесткопилки не поддерживается этим методом.
- [REST GetPositions](https://developer.tbank.ru/invest/api/operations-service-get-positions) — доступен JSON-интерфейс с Bearer-токеном.
- [Python SDK](https://developer.tbank.ru/invest/sdk/python_sdk/faq_python) и [требования подключения](https://developer.tbank.ru/invest/intro/developer/network) — при реализации проверить совместимость с Python 3.13 и доверие сертификатам без отключения TLS-проверки.
- [T-Invest MCP](https://developer.tbank.ru/invest/mcp) — отдельный способ предоставить ИИ-агентам инструменты брокера; не требуется для первого среза.

## 3. Пользовательские сценарии и UI

1. Войти и открыть `/settings`, раздел «Брокеры и торговля». Карточка Т-Инвестиций объясняет режим «Только чтение» и содержит ссылку на инструкцию выпуска токена банка.
2. Ввести токен в поле типа password и нажать «Подключить». Поле очищается после отправки; сохранённый токен никогда не выводится обратно. Сервер проверяет доступные счета и права.
3. Выбрать доступный открытый счёт. Показать имя, тип и маскированный идентификатор. При единственном счёте всё равно показать выбранный счёт пользователю. Недоступные типы имеют объяснение.
4. Открыть `/portfolio/brokers/t-invest`: выбранный счёт, статус, дата снимка, общая оценка в валюте ответа брокера, показатели доходности с точными подписями, деньги по валютам и позиции. Кнопки «Обновить», «Выбрать счёт» и «Отключить».
5. Позиция показывает инструмент, тип, валюту, количество и единицы, среднюю/текущую цену и единицы, доступную оценку/доходность, блокировку. Отсутствующие показатели — прочерк. Сопоставленный инструмент открывает карточку локальной аналитики; несопоставленный остаётся видимым без ссылки.
6. При сбое обновления последний успешный снимок остаётся доступен с предупреждением и временем получения. При пустом счёте — пустое состояние, при истёкшем/отозванном токене — предложение заменить токен.
7. Отключение требует подтверждения, удаляет секрет и сохранённые брокерские счета/снимки. Пользователь отдельно отзывает токен в банке; приложение не обещает отзыв у брокера.

В существующем `/portfolio` добавить переход «Портфель Т-Инвестиций», в Настройках — статус подключения и переход к нему. На узком экране позиции и показатели остаются читаемыми. Русские подписи и общий стиль кнопок по [16-working-process.md](./16-working-process.md).

## 4. Авторизация и хранилище секретов

- FR-34-01: все данные доступны только владельцу подключения. Проверять пользователя и владение на каждом запросе; идентификаторы счетов из браузера сверять с проверенным списком банка.
- FR-34-02: принимать только доступ «только чтение» для всех счетов, возвращённых проверкой GetAccounts. При неизвестных правах или полном доступе отклонять подключение без сохранения. Проверять права повторно при обновлении списка счетов. Не проверять права попыткой отправки ордера. Клиент брокера содержит только разрешённые методы чтения.
- FR-34-03: токен не хранится в PostgreSQL, профиле, cookie, localStorage, логах, сообщениях ошибок, командной строке или заданиях админ-раннера. В браузере он присутствует только во время ввода и отправки формы, без постоянного хранения. В БД сохраняется случайная ссылка на отдельный secret vault.
- FR-34-04: для текущего Windows-развёртывания использовать Windows Credential Manager через явный backend хранилища; секреты защищены Windows, доступны процессу под выделенной учётной записью ОС. Файловые plaintext-backend запрещены; если vault недоступен, подключение отключено. Для Linux/Docker потребуется отдельный адаптер vault и проектирование развёртывания; хранение секретов в обычном JSON не является fallback.
- FR-34-05: запись/замена секрета и БД выполняются с компенсацией при ошибке. Старый секрет удаляется после успешной замены. При отключении запрещается синхронизация, затем удаляется секрет; сбой удаления не выдаётся за успешное отключение и допускает повторную очистку. Audit хранит пользователя, действие, время, результат и безопасный код ошибки без токена/полного ответа банка.
- FR-34-06: проверять CSRF для изменяющих запросов с cookie-аутентификацией; страницы и ответы подключения — Cache-Control: no-store. В рабочем сетевом развёртывании нужен HTTPS; локальная разработка допускает loopback. TLS-проверку брокера не отключать.

## 5. Данные и синхронизация

Новые SQLAlchemy-модели и Liquibase-миграции:

| Сущность | Данные и ограничения |
|---|---|
| BrokerConnection | user_id, provider=t_invest, secret_ref, статус, selected_account_id, время успешного обновления, безопасный код последней ошибки, created_at/updated_at; UNIQUE(user_id, provider) |
| BrokerAccount | connection_id, внешний account_id, имя, тип, статус, access_level; UNIQUE(connection_id, account_id); выбранный счёт принадлежит тому же подключению |
| BrokerPortfolioSnapshot | account_id, fetched_at UTC, валюта и оценка портфеля, показатели доходности с единицами, нормализованный снимок позиций и денег в JSON; один последний успешный снимок на счёт |
| BrokerConnectionEvent | user_id, connection_id nullable, действие, результат, безопасный код, время; после удаления подключения остаётся минимальная запись аудита |

Денежные значения и количества преобразовывать из units/nano через Decimal, сохранять в JSON десятичными строками, без float. Позиции идентифицировать по instrument_uid/position_uid и доступным идентификаторам банка; хранить тип, валюту, единицы и блокировки. Не сохранять сырой ответ целиком. Не пересчитывать общую оценку простым quantity × price для фьючерсов/облигаций и не складывать разные валюты без конвертации.

Связь с локальным Security — nullable. Сопоставление по проверенным идентификаторам/типу и однозначному тикеру с торговым классом; совпадения одного тикера недостаточно. Не создавать локальные бумаги автоматически для неизвестных позиций.

Последовательность: GetAccounts → проверка прав/счёта → GetPortfolio + GetPositions → нормализация → атомарная запись снимка. Ответы двух методов не являются гарантированным биржевым снимком одного момента; показывать время получения приложением. Сбой обязательного метода не заменяет предыдущий снимок частичными данными. Смена счёта не показывает позиции предыдущего счёта как нового.

Клиент асинхронный, отдельный слой `app/brokers/t_invest`, без зависимости от LLM. Предпочтительно REST через существующий httpx; перед реализацией подтвердить контракты GetAccounts/GetPortfolio/GetPositions и поля прав по официальному API. Если REST не покрывает нужное поле, использовать асинхронный SDK. Адрес сервиса фиксирован конфигурацией, не вводится пользователем. Таймауты, ограниченные повторные попытки только для временных сбоев чтения, соблюдение 429; ошибки авторизации без повторов. Одно обновление подключения одновременно, повторный клик не создаёт параллельные запросы. Защита от записи снимка после отключения/замены токена через проверку версии подключения перед commit.

Первый срез обновляется вручную, без фонового расписания и новых scripts. После перезапуска приложения подключение и снимок сохраняются при доступности того же vault.

## 6. Предлагаемый API приложения

Все маршруты требуют авторизации; payload и ответы не возвращают токен. POST подключения содержит токен только во входной writeOnly-схеме. Не логировать тело.

| Метод | Назначение |
|---|---|
| GET /v1/brokers/t-invest | Статус подключения, счета, выбранный счёт, время последнего снимка |
| POST /v1/brokers/t-invest/connect | Проверить и сохранить токен; при замене сохранить действующее подключение до успеха проверки |
| POST /v1/brokers/t-invest/select-account | Выбрать принадлежащий подключению доступный счёт и получить первый снимок |
| POST /v1/brokers/t-invest/refresh | Обновить список счетов и снимок выбранного счёта |
| GET /v1/brokers/t-invest/portfolio | Последний снимок выбранного счёта и актуальность |
| DELETE /v1/brokers/t-invest | Отключить и удалить секрет/снимки |

Ошибки: 401 — нет сессии приложения; 404 — подключение/счёт недоступны этому пользователю; 409 — обновление уже идёт или состояние изменилось; 422 — недопустимый токен/права/счёт с безопасным пояснением; 502/503 — временный сбой брокера/vault. Авторизация брокера обозначается отдельным кодом, не маскируется под истечение сессии приложения. Веб использует тот же сервис; POST-формы защищены CSRF и стандартным redirect после действия.

## 7. Приёмка, проверки и выпуск

- Два пользователя не видят счета/снимки друг друга; подстановка чужого account_id не работает. Нет токена в ответах, БД, логах и HTML после отправки.
- Read-only принимается, full-access и неизвестные права отклоняются; неправильный/отозванный токен обрабатывается без потери текущего подключения при замене.
- Проверены пустой счёт, несколько счетов, отрицательные позиции, разные валюты, дробные количества, блокировки, неизвестные инструменты, особенности фьючерсов/облигаций, ошибки и 429.
- Проверены перезапуск, миграции, замена токена, сбои vault/БД, повторное обновление и отключение во время запроса. Удалённое подключение не возрождается результатом запроса.
- Python-тесты используют фикстуры брокера и тестовый vault без сети и реальных токенов; Playwright покрывает подключение, выбор счёта, портфель, сбой и отключение. Реальную проверку read-only выполняет пользователь после готовности интерфейса.
- Пройти pytest, compileall, smoke, Playwright, check/lint OpenAPI, проверку миграций. Секреты не включать в тестовые артефакты.

При реализации новые параметры подключения/vault зарегистрировать в `app/config.py` и документе эксплуатации. Инструкция пользователя: выпуск read-only токена → Настройки → подключение → выбор счёта → портфель → обновление/отключение. Перенести факты в 07/10/11/13/14/17, обновить [12-roadmap.md](./12-roadmap.md) и [27-user-settings.md](./27-user-settings.md), архивировать ТЗ по [32-docs-architecture.md](./32-docs-architecture.md). Подготовить рекомендацию стабильного тега после проверок; создание тега — по явному запросу.
