# 22. Источник «Сайты компаний» — ТЗ и дизайн

**Статус:** утверждено v1.0  
**Система:** NewsTrader Assistant  
**Связанные документы:** [20-news-sources-manager.md](./20-news-sources-manager.md), [04-functional-requirements.md](./04-functional-requirements.md), [10-api-specification.md](./10-api-specification.md), [14-web-interface.md](./14-web-interface.md), [13-operations.md](./13-operations.md), [12-roadmap.md](./12-roadmap.md)

## 1. Обоснование и цели

Закрывает пункт этапа 1 дорожной карты **«сайты компаний как источник»** ([12-roadmap.md](./12-roadmap.md)): расширение охвата источников новостей за счёт страниц новостей и пресс-релизов на сайтах эмитентов (прямые корпоративные новости, которые часто не попадают в агрегаторы).

- Требование: **FR-01-01** (P0, UC-08) — «система должна подключаться к множеству источников: новостные агентства, RSS, сайты компаний, Telegram-каналы, вебхуки» ([04-functional-requirements.md](./04-functional-requirements.md)).
- Смежное: News Sources Manager ([20-news-sources-manager.md](./20-news-sources-manager.md)) уже управляет персональными RSS-лентами; в веб-интерфейсе есть задел-вкладка **«Сайты»** на `/news` (сейчас помечена «(в планах)»).

**Цель первой версии (MVP):** собирать новости со **страницы-списка** сайта (пресс-релизы / список новостей) через безопасный HTTP-фетч и LLM-извлечение записей; полученные записи проходят штатный конвейер (фильтрация по графу, LLM-анализ, ингест) как обычные новости.

**Что не входит в MVP** (см. §8 «Ограничения и не-скоуп»): фетч и парсинг полного текста каждой статьи, настраиваемые CSS-селекторы, автоматическое обнаружение страниц-списков.

## 2. Функциональные требования

### 2.1. Пользовательские сценарии (UC)

- **UC-08 (новый):** пользователь добавляет сайт компании как источник новостей (URL страницы новостей), система проверяет доступность и безопасность URL, сохраняет сайт в персональном списке; коллектор периодически собирает записи со страницы и пропускает их через конвейер анализа.
- **UC-08a:** пользователь включает/выключает сайт, включает «LLM-разбор» (извлечение записей из HTML страницы через DeepSeek) и «Обход антибота» (браузерный фетч через Playwright при неудаче обычного HTTP).
- **UC-08b:** пользователь удаляет сайт из списка; кнопка «Вернуть стандартные сайты» восстанавливает предустановленный набор.

### 2.2. Требования (FR)

| ID | Требование | Приоритет |
|---|---|---|
| FR-S-01 | Управление сайтами: добавление, удаление, вкл/выкл, проверка доступности, редактирование URL/категории | P0 |
| FR-S-02 | SSRF-защита при добавлении и фетче: только http/https, запрет локальных/внутренних адресов (переиспользование `validate_feed_url` из `app/news/feed_check.py`) | P0 |
| FR-S-03 | Флаги источника: `use_llm` (LLM-извлечение записей из HTML), `use_browser` (фетч через headless-браузер при недоступности по HTTP) | P0 |
| FR-S-04 | Коллектор: безопасный фетч страницы (таймаут, лимит размера), извлечение записей `{title, link, description, published}`, конвертация в `RawArticle` | P0 |
| FR-S-05 | Интеграция с конвейером: `collect_news --sites` и ежедневный `daily_pipeline` собирают сайты наряду с RSS/Telegram; записи фильтруются по графу и анализируются LLM | P0 |
| FR-S-06 | Проверка доступности сайта: обновление `last_status`/`last_error`/`last_checked_at`, статусы ✓/✗ в интерфейсе | P0 |
| FR-S-07 | Категории сайтов (список `SOURCE_CATEGORIES` как у лент) | P1 |
| FR-S-08 | «Вернуть стандартные сайты» — предустановленный набор (не менее 2–3 сайтов-примеров) | P1 |

## 3. Модель данных

Изменений схемы **не требуется** — переиспользуется существующая модель `Source`:

| Поле | Значение для сайтов |
|---|---|
| `kind` | `"website"` (новые значения: `"rss"`, `"telegram"`, `"website"`) |
| `config` | `{"url": "https://company.ru/press"}` — URL страницы-списка новостей |
| `name` | название сайта/компании |
| `category` | категория из `SOURCE_CATEGORIES` (`биржа`/`геополитика`/`погода`/пусто) |
| `reputation_score` | репутация источника (по умолчанию 0.5) |
| `use_llm` / `use_browser` | флаги «LLM-разбор» / «Обход антибота» |
| `last_status` / `last_error` / `last_checked_at` | статус проверки ✓/✗ |
| `is_active` | вкл/выкл |

Пользовательские списки — таблица `user_sources` (как у лент). Миграции Liquibase не требуются (строковые поля уже существуют).

## 4. API

### 4.1. Универсальное API источников (существующее, расширение по `kind`)

Эндпоинты `/v1/sources` ([10-api-specification.md](./10-api-specification.md)) уже поддерживают `kind` в запросах/ответах. Для сайтов:

- `GET /v1/sources?kind=website` — список сайтов пользователя;
- `POST /v1/sources` с `{name, url, kind: "website", category}` — добавить сайт (с проверкой `validate_feed_url` → 400 при SSRF/невалидном URL);
- `PUT /v1/sources/{id}`, `DELETE /v1/sources/{id}`, `POST /v1/sources/check`, `POST /v1/sources/restore-defaults` — без изменений, работают для любого `kind`.

### 4.2. Веб-роуты вкладки «Сайты» (планируемые, `/news/site/*`)

По образцу существующих RSS-роутов `/news/rss/*` (все требуют авторизации; ответ — 303-редирект на `/news?tab=sites`, ошибки — через `?error=`):

| Роут | Назначение |
|---|---|
| `POST /news/site/add` | Добавить сайт: `{name, url, category}`; SSRF/невалидный URL → `?error=…` |
| `POST /news/site/remove` | Убрать сайт из списка пользователя: `{source_id}` |
| `POST /news/site/toggle` | Переключить флаг `use_llm`/`use_browser`: `{source_id, field}` |
| `POST /news/site/check` | Проверить доступность выбранных сайтов (`{ids}`, пусто — все) |
| `POST /news/site/update` | Редактирование URL/категории прямо в таблице (карандаш ✎, как у лент) |
| `POST /news/site/restore` | «Вернуть стандартные сайты» |

## 5. UI — вкладка «Сайты» на `/news`

Вкладка **«Сайты»** в `news.html` (сейчас `tab-disabled` «(в планах)») становится активной и повторяет структуру RSS-вкладки:

- **Таблица сайтов** (по `GET /v1/sources?kind=website`): Имя · URL · Категория (select) · Репутация · Статус (✓ работает / ✘ ошибка / не проверена) · Парсинг (галочки «LLM» и «Браузер») · Действия (✎ редактировать, ✕ удалить);
- **Кнопки**: «Проверить выбранные» (чекбоксы строк) и «Вернуть стандартные сайты»;
- **Форма «Добавить сайт»**: Название · URL · Категория; при невалидном URL — сообщение об ошибке (баннер `?error=`);
- Поведение тумблеров LLM/Браузер — мгновенный `fetch` + перезагрузка статуса, как у лент.

Переключение вкладок RSS ⇄ Сайты — через `?tab=rss|sites` (URL-параметр).

## 6. Коллектор — дизайн (`app/collectors/websites.py`)

```
fetch (httpx, SSRF-валидация + таймаут 10с + лимит 2 МБ из feed_check)
  └─ если пусто/ошибка и use_browser → fetch_with_playwright(url)
       └─ извлечение записей:
            штатный способ отсутствует (страница-список — не RSS) →
            если use_llm → parse_site_with_llm(html)  → [{title, link, description, published}]
       └─ конвертация в RawArticle(source_name=site.name)
```

- `parse_site_with_llm` — переиспользует `LLMClient` и промпт, аналогичный `parse_feed_with_llm` (`app/news/llm_parse.py`), но ориентированный на HTML-список новостей/пресс-релизов; возвращает `[]` при ошибке LLM.
- Функция `fetch_website(site) -> RawArticle[]` — по образцу `fetch_rss_feeds` (`app/collectors/rss.py`): безопасный фетч + фолбэки, логирование в stdout конвейера.
- Реестр источников: `get_website_sources(session)` в `app/news/sources_service.py` (по образцу `get_rss_feeds`, фильтр `kind == "website"`).

## 7. Тестирование (план, без реализации)

- **Unit:** `parse_site_with_llm` (мок LLM: валидный JSON, пустой ответ, markdown-обёртка, ошибка); `fetch_website` (SSRF-отказ, таймаут, фолбэк на браузер, лимит размера); сервис источников (`get_website_sources`, CRUD).
- **E2E (`tests/e2e/test_news_admin.py` или новый файл):** вкладка «Сайты» — рендер, добавление с невалидным URL → ошибка, toggle LLM/Браузер, удаление, «Вернуть стандартные сайты» (по образцу RSS-тестов); маркер `e2e`, прогон `pytest -m e2e`.

## 8. Ограничения и не-скоуп (MVP)

- **Не собирается полный текст статей** — только записи со страницы-списка (заголовок, ссылка, описание); полный текст — на потом.
- **Нет настраиваемых CSS-селекторов** и автоматического обнаружения страницы новостей — URL задаётся вручную.
- Сбор зависит от доступности сайта и корректности HTML; «Обход антибота» (Playwright) — best-effort.
- Мультиязычность сайтов (английский язык) — отдельный пункт этапа 1 roadmap, в этом ТЗ не рассматривается.
- Стандартный набор сайтов («Вернуть стандартные сайты») — наполняется позже, при первом включении функции.
