# 32. Архитектура документации — единый источник истины (SSOT)

**Статус:** утверждено v1.0
**Система:** NewsTrader Assistant

Документ фиксирует, как устроен и поддерживается комплект документации: какие документы за что отвечают, где живёт каждый факт и как фича-документы переходят в архив. Правила обязательны к выполнению и продублированы в [16-working-process.md](./16-working-process.md) §2.1.

## 1. Проблема

Комплект вырос до 30+ файлов, где одни и те же факты (команды запуска, переменные `.env`, эндпоинты API, маршруты веба, статусы фич, версии) копировались в 3–6 документов. При изменении факта в одном месте остальные устаревали — фактический рассинхрон уже случался (номер версии комплекта и число документов в `AGENTS.md` расходились с `docs/README.md`).

## 2. Принципы

1. **SSOT (Single Source of Truth) / DRY.** У каждого факта ровно один «дом». Все остальные места — однострочное упоминание + ссылка.
2. **Разделение по типу документа** (по мотивам Diátaxis): учебный маршрут (17), эксплуатационные how-to (13), справочники (07, 10, 14, 15), объяснения (01, 06, 08, 09), процесс (16). Типы не смешиваются: справочные таблицы не копируются в учебные документы.
3. **Жизненный цикл фича-ТЗ** (по мотивам ADR): ТЗ существует, пока фича проектируется и реализуется; после реализации фактическая правда переносится в базовые документы, а ТЗ сокращается до записи о решении и уходит в `docs/archive/`.

## 4. Жизненный цикл фича-документа

```
проект (draft) → утверждено → реализовано → архив (docs/archive/)
```

- Новый документ создаётся только для **проектируемой** фичи; в README он регистрируется с пометкой «проект».
- При завершении реализации: факты переносятся в базовые документы по карте владения (один раз), фича-документ сокращается до ADR-записи (обоснование → принятое решение → где живут факты → открытые остатки) и перемещается в `docs/archive/` (`git mv`, история сохраняется).
- README ведёт раздел «Архив» со ссылками на ADR-записи; активным источником правды архивный документ не является.
- Фича считается закрытой только после переноса фактов и архивации.

## 5. Правила против разрастания

1. Один факт — один дом; копирование содержания запрещено, допускается упоминание + ссылка.
2. Версии — только в шапке своего документа; версия комплекта — только в README.
3. Новый факт добавляется в его дом; если он понадобился в третьем месте — оформляется ссылкой.
4. Если раздел базового документа разросся (~300+ строк) — выносится в отдельный документ с ссылками, а не копируется.
5. Чеклист перед коммитом ([16-working-process.md](./16-working-process.md) §7) включает пункт «новые дубли не внесены».
6. Перспектива: скрипт-проверка битых относительных ссылок и захардкоженных версий вне README (отдельная задача).
