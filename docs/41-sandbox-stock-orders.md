# 41. Рыночные заявки на акции в Sandbox

**Статус:** утверждено v1.1 (уточнено поведение поиска).

Постановка: [покупка и продажа акций в Sandbox](../tasks/sandbox-stock-orders.md). [Интерактивный макет](./design/sandbox-stock-orders.html) согласован 12.11.2026. Контракт брокера: [REST-профиль Sandbox](./openapi/t-invest-sandbox.openapi.yaml).

## Сценарий в портфеле

На вкладке «Портфель» открытого счёта Sandbox «Купить акцию» открывает форму с поиском по части тикера или названия без учёта регистра. При пустом поле список показывает доступные акции из избранного пользователя. После загрузки каталога ввод каждого символа сразу фильтрует весь каталог в браузере и обновляет число совпадений. Очистка возвращает избранное. Совпадения по тикеру выводятся первыми; строка результата показывает тикер, название и класс торгов для различения одноимённых инструментов. Выбор доступен мышью и клавишами стрелок и Enter. Изменение текста сбрасывает выбор и блокирует отправку до нового выбора.

«Изменить» в строке поддерживаемой позиции открывает ту же форму с зафиксированной бумагой и переключателем «Купить / Продать». Форма показывает доступное к продаже число акций и полных лотов. Если доступность не удалось получить, продажа отключена до обновления данных; нулевой остаток отображается отдельно от ошибки загрузки.

В форме видны счёт, количество лотов, размер лота и ориентировочная сумма без комиссии. Сумма равна последней известной цене за акцию × размер лота × число лотов. Если цены нет, показывается «Оценка недоступна». Кнопка отправляет рыночную заявку сразу; на время запроса отключается. При смене счёта открытая форма сбрасывается; ответ на уже отправленную заявку не обновляет портфель другого счёта.

## API приложения

Все пути ниже относительно `/v1/brokers/t-invest/sandbox/accounts/{account_id}`. Требуется авторизованный пользователь. Счёт проверяется по актуальным счетам его Sandbox-подключения, включая статус открытия и доступ на торговлю. Ответы с данными счёта возвращаются с `Cache-Control: no-store`. Для отправки применяются существующие проверки источника запроса.

| Метод и путь | Контракт |
|---|---|
| `GET /instruments` | Каталог доступных к покупке рублёвых акций из Sandbox `Shares`: `instrument_uid`, `ticker`, `name`, `class_code`, `is_favorite`. Браузер загружает каталог для выбранного счёта и фильтрует его локально. |
| `GET /instruments/{instrument_uid}/order-details` | Актуальные размер лота, последняя цена в рублях или `null`, доступные акции и полные лоты или `null` при ошибке чтения позиции. |
| `POST /orders` | Тело: `operation_key` (UUID), `instrument_uid`, `side` (`buy` / `sell`), `lots` (положительное целое число). |
| `GET /orders/{operation_key}` | Статус ранее отправленной заявки на этом счёте; для незавершённой заявки запрашивает брокера без выставления новой. |

Ответ заявки содержит ключ операции, статус, запрошенные и исполненные лоты (исполненные могут быть неизвестны), и безопасное сообщение при отказе или неопределённости. Чужой или недоступный счёт и неизвестная для этого счёта заявка дают 404; конфликт ключа или занятое подключение — 409; невалидные параметры, неподходящий инструмент и превышение доступного количества — 422. Ошибка предварительного чтения отображается как недоступность данных; заявка при этом не отправляется.

## Проверки и отправка

- Идентификатор заявки привязан к UID инструмента, а не к отображаемому тикеру. Выдача поиска и серверная проверка перед отправкой допускают только акции в рублях, доступные для торговли через API, с положительным размером лота и разрешённым направлением. Для проверки используются актуальные метаданные инструмента из Sandbox.
- Перед продажей читается `GetSandboxPositions`. Доступные акции берутся из незаблокированного `securities[].balance` соответствующего UID, с нижней границей 0; `blocked` повторно не вычитается. При явной биржевой блокировке или отсутствии позиции доступно 0. Доступные лоты — целая часть от деления доступных акций на размер лота. При ошибке получения или разбора позиции продажа не отправляется.
- Сервер отправляет `PostSandboxOrder` с `ORDER_TYPE_MARKET`, направлением, количеством в лотах, UID и ID счёта. `orderId` равен `operation_key`, поле цены не передаётся, `confirmMarginTrade=false`. Достаточность денег и возможность исполнения определяет брокер; оценка суммы не служит проверкой средств. Используется адрес Sandbox и токен только этого подключения.
- Используется существующая таблица `broker_sandbox_actions`: действие `stock_order`, исходные параметры и хеш запроса, состояние отправки, нормализованный результат брокера. Миграция не требуется. Проверка и резервирование выполняются под блокировкой подключения; запись заявки фиксируется до вызова брокера. Повтор с тем же ключом и теми же параметрами возвращает имеющуюся запись, другой набор параметров с этим ключом отклоняется. Токены и сырые ответы в журнал действий не записываются.

## Статус и обновление портфеля

Форма различает статусы «Отправляется», «Принята», «Частично исполнена», «Исполнена», «Отклонена», «Отменена» и «Статус неизвестен». HTTP-успех сам по себе не означает исполнения: статус и фактическое число исполненных лотов берутся из ответа брокера. Тайм-аут, ошибка транспорта или неполный ответ дают неизвестный статус; новая заявка автоматически не отправляется.

Для принятой, частично исполненной или неизвестной заявки доступно «Проверить статус». Если получен биржевой ID, используется он; иначе `GetSandboxOrderState` вызывается с исходным UUID и `ORDER_ID_TYPE_REQUEST`. Если брокер не находит заявку по ключу, неизвестный результат сохраняется. Брокер хранит статусы песочницы семь дней; после окончания окна приложение показывает последний известный результат без повторной отправки. Браузер сохраняет ссылку на незавершённую заявку для того же счёта при перезагрузке страницы; сервер повторно проверяет владельца при чтении.

При подтверждении нового исполненного количества обновляются снимок портфеля и рублёвый остаток из брокера. При закрытии позиции строка исчезает после успешного обновления. Если обновить портфель не удалось, исполнение остаётся подтверждённым, а пользователю предлагается обновить портфель. Обновление не инициирует новую сделку.

## Приёмка

- Автоматически: поиск и выбор с клавиатуры; покупка из портфеля; покупка и продажа через «Изменить»; смена счёта; расчёт из незаблокированного остатка и запрет продажи сверх него; отказ для чужого счёта, рабочего контура или недоступной бумаги.
- С имитацией брокера: двойная отправка и конфликт ключа; отказ, частичное исполнение и тайм-аут с проверкой по UUID; ошибка обновления после исполнения. Проверить, что по одному ключу сделан максимум один вызов выставления заявки и что проверка статуса не выставляет заявку.
- Вручную на собственном пополненном счёте Sandbox: купить один лот, сверить количество, долю и рублёвый остаток прямым чтением MCP, затем продать тот же лот и сверить портфель. Для этого прогона DeepSeek не требуется.
- При реализации пройти pytest, compileall, Playwright и проверки OpenAPI. Описать поставленную функциональность в документах по веб-интерфейсу, API, эксплуатации и быстрому старту; обновить дорожную карту и перенести решения из проектной спецификации по правилам архивации.
