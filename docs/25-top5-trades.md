## 1. Обоснование и цели

Текущий Теханализ в LLM (docs/23) работает **по одной конкретной ценной бумаге**: пользователь на карточке `/securities/{ticker}` запускает анализ, в ответ получает карточку-результат (вердикт, вход, TP, SL) и по клику — страницу `/tech_analysis/{id}` с тремя сценариями «Моя стратегия» (A/B/C).

**Проблема:** если пользователь следит за группой акций (например, «зерновые» или «металлургия»), ему приходится запускать Теханализ по каждой бумаге по отдельности, а затем вручную сравнивать результаты, чтобы понять, какая акция и сделка по ней сейчас наиболее привлекательна для входа.

**Цель:** дать пользователю возможность:
- выбрать сохранённый **шаблон акций** (обобщённый механизм «Шаблоны инструментов»); 
- запустить **Теханализ в LLM по всем акциям шаблона** одной кнопкой;
- получить на отдельной странице **рейтинг Top-5 лучших сделок** для входа на рынок (одна лучшая стратегия конкретной бумаги, а не три сценария одной акции);
- развернуть по клику на бумагу **все 3 сценария** «Моя стратегия» (A/B/C);
- ранжировать кандидатов по понятным метрикам, включая **Expected R / ожидаемый результат**.

**Не-цели:**
- Не изменяет движок стратегий (`app/strategy/engine.py`) и внутренние вердикты — это внешний по отношению к системе разбор (как и одиночный Теханализ).
- Не выполняет автоматических сделок и не выставляет ордера (дальний TODO брокера см. 12-roadmap).
- Не добавляет новых внутридневных (минутных) данных — Теханализ использует текущий набор данных (дневные свечи, индикаторы, OI для фьючерсов), как в docs/23.

## 2. Термины

| Термин | Значение |
|---|---|
| **Шаблон инструментов** | Обобщённый механизм списков бумаг (рефакторинг «Шаблонов фьючерсов»). Один шаблон — именованный список тикеров с полем `kind`: `stock` (акции) или `futures` (фьючерсы) |
| **Батч Теханализа** | Один запуск «отправить на Теханализ» для группы акций шаблона: создаёт по обычному одиночному анализу на каждую акцию + лёгкий ярлык-батч |
| **Expected R (ожидаемый результат)** | Мера ценности сделки. Для сценария: `Expected R = prob × rr − (1 − prob) × 1`, где `prob` — вероятность реализации сценария, `rr` — Risk/Reward сценария. Отрицательный Expected R — сделка в среднем убыточна |
| **R/R (Risk/Reward)** | Отношение потенциальной прибыли к риску. Полезно, когда целевые уровни и стоп заданы ценами |
| **Топ-5** | До пяти лучших сделок (одна лучшая стратегия конкретной бумаги) по метрикам из §7 |

## 3. Пользовательские сценарии (UC)

- **UC-01. Выбор шаблона.** Пользователь переходит на страницу (например `/top5`), видит список сохранённых «Шаблонов инструментов», выбирает шаблон с акциями (`kind=stock`).
- **UC-02. Запуск батча.** Нажимает кнопку **«Отправить на Теханализ в LLM»** (рядом — выбор **LLM для анализа**: Авто/ChatGPT/DeepSeek, по аналогии с одиночным анализом, docs/23 §10). Система запускает фоном Теханализ по **каждой акции** шаблона (по механикам одиночного Теханализа, docs/23 §9). На странице отображается **прогресс активного батча** (авто-поллинг `/v1/top5/{id}/status` каждые ~4 с; при завершении страница перезагружается) и **история запусков** по шаблону с раскрытием статусов по акциям. Выбранный `provider` передаётся в запросы анализа.
- **UC-03. Просмотр Top-5.** После завершения пользователь видит рейтинг до 5 лучших сделок/акций: бумага, направление (**LONG / SHORT / Выжидать** — включая вердикт WAIT, чтобы результат был виден, даже если по всем акциям «удержание»), вход, стоп, цель, R/R, вероятность, **Expected R**. Ранжирование по Expected R. В «Истории запусков» клик по строке батча раскрывает его собственный Top-5 и состав по акциям.
- **UC-04. Раскрытие сценариев.** Клик по строке/карточке бумаги раскрывает **все 3 сценария** «Моя стратегия» (A/B/C) данной акции (перенос содержимого карточек со страницы `/tech_analysis/{id}`).
- **UC-05. Переиспользование результатов.** Результаты по каждой акции сохраняются как обычные анализы (`tech_analyses`) и видны на карточке бумаги `/securities/{ticker}` — повторно LLM не вызывается, если анализ по акции уже актуален.
- **UC-06. Открыть полный ответ.** Клик на бумагу дополнительно ведёт на существующую страницу `/tech_analysis/{id}` полного ответа (Markdown + сценарии).

## 5. Рефакторинг «Шаблоны фьючерсов» → «Шаблоны инструментов»

Нужен общий механизм списков **акций и фьючерсов** в одном хранилище с полем типа, чтобы разные функции могли брать из шаблона только нужную категорию сущностей:

### 5.1. Модель «Шаблона инструментов»

Обобщаем таблицу `futures_templates`:
- **Обратная совместимость:** таблица остаётся `futures_templates` (не пересоздаём), добавляется колонка `kind VARCHAR(20) NOT NULL DEFAULT 'futures'`. Существующие шаблоны без явного значения автоматически трактуются как `futures` (прежнее поведение сохраняется).
- Поле `kind`: `'stock'` | `'futures'`. Один шаблон содержит однородные сущности одного kind.
- Название в UI — **«Шаблоны инструментов»** (страница `/admin/templates`), старое имя/роут `futures-templates` остаётся как редирект/алиас для совместимости.
- Редактор поддерживает загрузку как фьючерсов (из `/v1/indicators/futures`, MOEX ISS), так и акций (из справочника БД `securities`, `security_type='stock'`, см. §5.2).

SQLAlchemy-модель `FuturesTemplate` (или переименованная `InstrumentTemplate`) меняется вместе с миграцией (правило 6 / 16 §6): добавляется `kind`. Для минимального риска переименование класса/schema можно как «слой совместимости» (алиас), но миграция обязательна.

### 5.2. Список акций для редактора

Список акций берём из **справочника БД** (таблица `securities`, `security_type='stock'`, уже наполнена после `seed_db`). Поля для карточки-бейджа: `ticker`, `name`, `sector`, `market`, `currency`. Фильтры редактора: поиск по тикеру/названию, фильтр по сектору. Загрузка — из БД (детерминированно, без зависимости от MOEX на этапе редактирования).

## 7. Метрики, скоринг и ранжирование Top-5

### 7.1. Структура сценария в JSON-блоке (расширение промта)

Промт `docs/promt_tech_analize.md` §12 и `app/tech_analysis/parser.py` расширяются: каждый сценарий в JSON-блоке дополнительно содержит **числовые** `rr` (Risk/Reward, ≥0) и `probability` (0..1). Пример:

```json
{
  "verdict": "BUY | SELL | WAIT",
  "entry": "...",
  "tp": "...",
  "sl": "...",
  "scenario_a": {
    "title": "...", "entry": "...", "stop": "...", "targets": "...", "why": "...",
    "probability": 0.65,
    "rr": 2.5
  },
  "scenario_b": { "...": "...", "probability": 0.25, "rr": 1.8 },
  "scenario_c": { "...": "...", "probability": 0.10, "rr": 0.5 }
}
```

Правила:
- `probability` и `rr` — **числа** (не строки). Если LLM вернул строку/отсутствует — парсер считает 0/None и делает этот сценарий непригодным для ранжирования (но анализ остаётся успешным, как в docs/23).
- Основной сценарий (A) должен иметь наибольшую вероятность.

### 7.2. Expected R

Для каждого сценария каждой акции:

```
Expected R = prob × rr − (1 − prob) × 1
```

Пример из ТЗ: `prob=0.6, rr=2.5` → `0.6×2.5 − 0.4×1 = 1.50 − 0.40 = +1.10R`. Отрицательное значение — сделка в среднем убыточна.

### 7.3. «Лучшая» стратегия бумаги

Для каждой акции в Top-5 показывается **одна лучшая стратегия** — сценарий с **наибольшим Expected R** среди A/B/C при `verdict=BUY/SELL/WAIT` (WAIT «выжидать» включается, чтобы результат был виден даже при «удержании» по всем акциям). Если у акции нет ни одного сценария с валидными `probability` и `rr` — кандидат исключается из Top-5 (но его анализы всё равно сохранены и доступны на карточке).

### 7.4. Ранжирование Top-5

- **По умолчанию сортировка — по убыванию `Expected R`** (только валидные кандидаты).
- **Вторичные метрики** для сравнения/сортировки:
  - потенциальная доходность (цель − вход), %
  - R/R сценария
  - вероятность сценария (`probability`)
  - риск до стопа (вход − стоп), %; лимит по качеству (например, ≤ порога из макета).
- **Score (обобщённый)** — вспомогательный рейтинг, приближённый к макету (распределение весов: Expected R/уверенность, R/R, риск до стопа, качество структуры). Точные веса калибруются на этапе реализации; главный ранжирующий ключ — Expected R.

### 7.5. Отрисовка Top-5 (дизайн)

Страница повторяет `docs/designer/template_top5_stock.html`:
- Шапка: заголовок «Отбор сделок — Top 5», выбор шаблона, кнопка запуска.
- Мета-карточки сверху: «Кандидатов», «Прошли фильтры», «Лучший Expected R».
- Таблица: `# · Бумага/стратегия · Направление · Вход · Стоп · Цель · R/R · Риск · Score · Expected R`.
- Клик по строке раскрывает блок с **трёмя карточками сценариев A/B/C** данной акции (перенос с `/tech_analysis/{id}`).

Веб-страницы:
- `GET /top5` — выбор шаблона + запуск + просмотр Top-5 (раскрытие сценариев).

Все эндпоинты требуют аутентификации (Bearer-токен или cookie `nt_token`, как прочие `/v1` приватные).

## 9. Этапы исполнения батча

По образцу одиночного Теханализа (docs/23 §9), на фоновых asyncio-тасках:

1. Чтение шаблона (`kind=stock`), дедупликация тикеров.
2. Для каждого тикера: если есть **актуальный** успешный анализ (свежесть — параметр, например ≤ N часов на тикер в батче) — переиспользовать; иначе запустить одиночный Теханализ (`app/tech_analysis/service.py`), связав запись `batch_id`.
3. Прогресс: `done`/`failed` инкрементируется по завершении каждого анализа.
4. По окончании: статус батча `success` (все ок) / `partial` (часть сбоев) / `failed` (все сбои); при запуске батча активная запись на тикер не создаётся повторно (как FR-23-10).
5. На каждой акции результат пишется как обычный анализ (`tech_analyses`) — доступен на карточке бумаги и на `Scenarios` странице.

**Ограничение состава (FR-25-12):** число акций в одном батче ограничено конфигом (например `TOP5_MAX_INSTRUMENTS`, по умолчанию 20) — контроль стоимости и длительности LLM-запросов.

```
# Пути/лимиты переиспользуют общие настройки Теханализа (CHATGPT_*, LLM_*, TECH_ANALYSIS_PROMPT_FILE)
```

## 11. Промт (изменения в `docs/promt_tech_analize.md`)

- §12 JSON-блок дополняется числовыми `probability` и `rr` на сценарий (см. §7.1).
- Текстовая инструкция уточняет: оценивать `probability` (0..1) и `rr` (Risk/Reward, ≥0) для каждого сценария; основной сценарий — наибольшая вероятность; `rr<0`/невалидные значения не допускаются (при отсутствии — пусто).
- Остальной промт не меняется; обратная совместимость: одиночный Теханализ по-прежнему работает, отсутствие `probability`/`rr` не ломает карточку (ропадает только из Top-5).

## 12. Регистрация скриптов/эндпоинтов в админке

- Страница «Шаблоны инструментов» (`/admin/templates`) — обобщение `/admin/futures-templates` (алиас старого роута сохраняется).
- Батч-запуск Top-5 — пользовательская (не админская) функция на `/top5`; отдельный скрипт не требуется (запуск через существующий фоновый механизм Теханализа). При необходимости — вспомогательный скрипт в `SCRIPTS` (опционально).

## 13. Безопасность и правовые аспекты

- Используются открытые данные MOEX ISS и справочник БД — новых секретов нет.
- `probability`/`conf` — **оценка модели/аналитика, а не статистически подтверждённая вероятность**; дисклеймер на странице Top-5 (как в `11-security-compliance.md` и макете).
- Ответы LLM рендерятся через санитизацию (как в docs/23) — защита от инъекций.
- Данные live-котировок — публичные, но эндпоинты Top-5 требуют аутентификации.

## 14. Ограничения и не-скоуп (первая версия)

- Топ-5 строится по **акциям** из шаблона `kind=stock`; фьючерсы в этом рейтинге не участвуют (для них нет необходимости в ранжировании групп — они покрываются реальным временем/OI, docs/24).
- `probability` и `rr` полагаемся на оценку LLM; при отсутствии валидных значений сценарий исключается из ранжирования (анализ сохраняется).
- Батч не запускает параллельно больше, чем позволяет лимит; переиспользование актуальных анализов ограничивает стоимость.
