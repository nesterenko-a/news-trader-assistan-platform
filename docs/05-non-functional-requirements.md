# 05. Нефункциональные требования

**Статус:** черновик v0.2  
**Система:** NewsTrader Assistant

Требования к качеству системы. Целевые значения на старте — ориентировочные и уточняются по результатам нагрузочного тестирования.

## NFR-01. Производительность

| ID | Требование | Целевое значение |
|---|---|---|
| NFR-01-01 | Время формирования вердикта по бумаге | ≤ 60 секунд при наличии свежих данных |
| NFR-01-02 | Время ответа на запрос ленты новостей | ≤ 3 секунды |
| NFR-01-03 | Задержка между публикацией новости и её появлением в системе | ≤ 15 минут |
| NFR-01-04 | Поддерживаемое количество одновременных пользователей | ≥ 100 |
| NFR-01-05 | Объём обрабатываемых новостей в сутки | ≥ 2 000 |
| NFR-01-06 | Кэширование повторяющихся запросов для снижения нагрузки | обязательно |

## NFR-02. Надёжность и доступность

| ID | Требование | Целевое значение |
|---|---|---|
| NFR-02-01 | Доступность сервиса | ≥ 99,5% в месяц |
| NFR-02-02 | Обработка сбоев внешних источников: повторные попытки, отложенная очередь | обязательно |
| NFR-02-03 | Восстановление после сбоя: перезапуск сборки продолжает с контрольной точки | обязательно |
| NFR-02-04 | Внезапная недоступность биржевого источника не должна ломать выдачу исторических данных | обязательно |

## NFR-03. Безопасность

| ID | Требование |
|---|---|
| NFR-03-01 | Хранение паролей и ключей только в зашифрованном виде |
| NFR-03-02 | Передача данных только по защищённым каналам (TLS) |
| NFR-03-03 | Изоляция данных пользователей друг от друга |
| NFR-03-04 | Журналирование действий администраторов (audit log) |
| NFR-03-05 | Защита от типовых атак: инъекции, подбор ключей (rate limiting), XSS |
| NFR-03-06 | Регулярное обновление зависимостей и сканирование уязвимостей |

## NFR-04. Точность и качество анализа

| ID | Требование | Целевое значение |
|---|---|---|
| NFR-04-01 | Точность определения тональности на валидационном наборе | ≥ 85% |
| NFR-04-02 | Доля новостей с корректно извлечёнными сущностями | ≥ 80% |
| NFR-04-03 | Система должна фиксировать уверенность каждой модели и отказываться от вывода при её недостаточности | обязательно |
| NFR-04-04 | Метрика качества вердиктов (сравнение с фактическим движением цены) | регулярно отслеживается, цель ≥ 55% верных направлений |
| NFR-04-05 | Воспроизводимость: повторный анализ тех же данных даёт тот же результат (с учётом версии моделей) | обязательно |

## NFR-05. Масштабируемость

| ID | Требование |
|---|---|
| NFR-05-01 | Горизонтальное масштабирование вычислительных компонентов (анализ, стратегия) |
| NFR-05-02 | Масштабирование хранения без потери данных (партиционирование, архивация) |
| NFR-05-03 | Очереди задач для обработки пиковых нагрузок (например, публикация отчётности в один день) |

## NFR-06. Наблюдаемость

| ID | Требование |
|---|---|
| NFR-06-01 | Логирование ключевых операций: сбор, анализ, генерация вердикта |
| NFR-06-02 | Метрики: время ответа, доля ошибок, глубина очередей, точность моделей |
| NFR-06-03 | Трейсинг цепочки «новость → вердикт» для диагностики |
| NFR-06-04 | Алерты для команды при падении ключевых метрик ниже порога |

## NFR-07. Совместимость и доступ

| ID | Требование |
|---|---|
| NFR-07-01 | Веб-интерфейс работает в актуальных версиях основных браузеров |
| NFR-07-02 | API стабилен: изменение формата выпускается с версионированием |
| NFR-07-03 | Документация API всегда соответствует последней версии |

## NFR-08. Локализация

| ID | Требование |
|---|---|
| NFR-08-01 | Интерфейс поддерживает русский язык на старте, английский — по мере развития |
| NFR-08-02 | Дата/время и валюта отображаются согласно настройкам пользователя |
