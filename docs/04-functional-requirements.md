# 04. Функциональные требования

**Статус:** утверждено v1.0  
**Система:** NewsTrader Assistant

Каждое требование имеет идентификатор, приоритет и связь со сценариями (UC) из [03-user-scenarios.md](./03-user-scenarios.md).

Приоритеты: **P0** — ядро, без него система не работает; **P1** — важно для полноценного продукта; **P2** — расширение.

## FR-01. Сбор и нормализация новостей

| ID | Требование | Приоритет | Связь |
|---|---|---|---|
| FR-01-01 | Система должна подключаться к множеству источников: новостные агентства, RSS, сайты компаний, Telegram-каналы, вебхуки | P0 | UC-08 |
| FR-01-02 | Система должна сохранять для каждой новости: заголовок, текст, дату публикации, источник, URL, язык | P0 | UC-01, UC-02 |
| FR-01-03 | Система должна выполнять дедупликацию: перепечатки и похожие новости группируются в кластер | P0 | UC-02 |
| FR-01-04 | Система должна оценивать и хранить репутацию источника (скоринг) | P1 | UC-02 |
| FR-01-05 | Система должна поддерживать русский и английский языки источников | P1 | UC-01 |
| FR-01-06 | Администратор должен иметь возможность добавлять/отключать источники и менять их скоринг | P1 | UC-08 |
| FR-01-07 | Система должна логировать ошибки сбора и показывать статистику по источникам | P1 | UC-08 |

## FR-02. Анализ текстов

| ID | Требование | Приоритет | Связь |
|---|---|---|---|
| FR-02-01 | Система должна определять тематику новости (макроэкономика, отрасль, компания, геополитика, регуляторика, прочее) | P0 | UC-01 |
| FR-02-02 | Система должна определять тональность (позитив/негатив/нейтрально) по каждой вовлечённой сущности | P0 | UC-01, UC-02 |
| FR-02-03 | Система должна извлекать сущности: компании, тикеры, валюты, сырьё, индексы, персоны, регионы, события | P0 | UC-01 |
| FR-02-04 | Система должна извлекать ключевые факты и числовые значения (ставки, цены, прибыль, прогнозы) | P1 | UC-01 |
| FR-02-05 | Система должна вычислять значимость новости (impact score) с учётом затухания во времени | P0 | UC-01, UC-04 |
| FR-02-06 | Система должна хранить версию модели анализа и дату анализа для воспроизводимости | P1 | UC-06 |

## FR-03. Knowledge graph взаимосвязей

| ID | Требование | Приоритет | Связь |
|---|---|---|---|
| FR-03-01 | Система должна хранить граф сущностей (компании, отрасли, сырьё, валюты, индексы, макроиндикаторы, регионы) | P0 | UC-01 |
| FR-03-02 | Система должна хранить рёбра влияния с параметрами: направление (+/−), сила, характер (прямое/косвенное), уверенность, источник связи | P0 | UC-01 |
| FR-03-03 | Система должна уметь строить цепочки влияния «событие → … → целевая бумага» | P0 | UC-01 |
| FR-03-04 | Система должна поддерживать дополнение графа новыми связями, обнаруженными в контенте (с ручным подтверждением) | P1 | UC-08 |
| FR-03-05 | Система должна хранить базовый набор связей, введённый аналитиками (курируемые связи) | P0 | UC-01 |
| FR-03-06 | Система должна уметь объяснять каждое ребро: почему связь существует, на чём основана | P0 | UC-01 |

## FR-04. Биржевые данные

| ID | Требование | Приоритет | Связь |
|---|---|---|---|
| FR-04-01 | Система должна получать и хранить котировки (цена, объём, минимум/максимум дня) | P0 | UC-01 |
| FR-04-02 | Система должна рассчитывать технические индикаторы: RSI, MACD, скользящие средние, уровни поддержки/сопротивления, волатильность | P0 | UC-01 |
| FR-04-03 | Система должна вести макроэкономический календарь: заседания ЦБ, публикации CPI/PMI/ВВП, сезоны отчётностей | P1 | UC-01, UC-04 |
| FR-04-04 | Система должна сопоставлять события календаря с потенциально затронутыми бумагами | P1 | UC-01 |
| FR-04-05 | Система должна корректно обрабатывать периоды, когда биржа закрыта | P1 | UC-01 |

## FR-05. Генерация стратегии

| ID | Требование | Приоритет | Связь |
|---|---|---|---|
| FR-05-01 | Система должна формировать вердикт: ПОКУПКА / ПРОДАЖА / УДЕРЖАНИЕ | P0 | UC-01 |
| FR-05-02 | Система должна указывать горизонт стратегии: кратко-/средне-/долгосрочный | P0 | UC-01 |
| FR-05-03 | Система должна указывать уровень уверенности с перечнем факторов, которые могут его изменить | P0 | UC-01 |
| FR-05-04 | Система должна указывать справочные уровни: вход, take-profit, stop-loss (с оговоркой об информационном характере) | P1 | UC-01 |
| FR-05-05 | Система должна при недостатке данных возвращать «недостаточно информации» вместо выдуманного вердикта | P0 | UC-01 |
| FR-05-06 | Система должна формировать обоснование: цепочки влияния с цитатами, ссылками и индикаторами | P0 | UC-01 |
| FR-05-07 | Система должна показывать контраргументы и ключевые риски | P0 | UC-01 |
| FR-05-08 | Система должна ссылаться на научные/аналитические работы, если они использовались | P1 | UC-01 |
| FR-05-09 | Система должна пересчитывать вердикт при появлении новых значимых новостей по бумаге | P1 | UC-01, UC-04 |
