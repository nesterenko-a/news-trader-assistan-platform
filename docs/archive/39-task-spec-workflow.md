# 39. Процесс task → spec → implementation

**Статус:** архив, реализовано v1.1

## Обоснование

Реализация новых задач должна начинаться после отдельных согласований постановки и спецификации. Постановка согласована в PR #7, спецификация — в PR #8. Исходные документы доступны в истории Git.

## Решение

Введён проектный навык task-spec-workflow, связанный с AGENTS.md. Этапы фиксируются отдельными ветками от master после слияния предыдущего этапа. Валидатор принимает типы tasks/spec, сохраняя прежние типы и проверку формата. При полном выполнении файл задачи удаляется без архивной копии; при частичном остаётся с остатками.

## Актуальные источники

- [Регламент](../16-working-process.md#11-постановка-спецификация-и-реализация-новых-задач) — согласования, этапы, коммиты и закрытие.
- [Архитектура документации](../32-docs-architecture.md#файлы-задач-и-спецификации) — владение файлами и жизненный цикл.
- [Проектный навык](../../.agents/skills/task-spec-workflow/SKILL.md) — инструкции агенту.
- [Валидатор](../../tools/git_checks.py) и [проверки сообщений](../../tests/test_git_checks.py).

## Закрытие

Критерии постановки реализованы: навык добавлен и подключён, согласования разделены, ветвление и префиксы согласованы, полное/частичное закрытие определено. Файл tasks/task-spec-workflow.md удалён обычным Git-изменением; постановка остаётся в истории, отдельный архив задач не создаётся. Открытых остатков нет.
