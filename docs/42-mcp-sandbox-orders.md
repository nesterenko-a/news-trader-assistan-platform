# 42. Ручные заявки через MCP Т‑Инвестиций в Sandbox

**Статус:** утверждено v1.2 (согласованный макет).

## Объём

Владелец открытого счёта Sandbox может купить или продать рублёвую акцию через MCP. Первый срез использует рыночную заявку в целых лотах и явное подтверждение в веб-интерфейсе. Действующая форма Sandbox служит основой сценария. Пользователь видит контур и способ отправки заявки. При недоступности MCP интерфейс сообщает причину. Переключение на REST требует отдельного действия пользователя. [Постановка](../tasks/mcp-sandbox-orders.md).

## Проверка инструментов и доступа

Выгрузить схемы через существующую диагностику MCP с `include_schemas: true` для Sandbox и рабочего контура. Сопоставить фактические инструменты выставления заявки, чтения статуса, счёта и позиций. Проверить поддержку ключа заявки, поиска по этому ключу при отсутствии биржевого ID, числа исполненных лотов и кодов отказа. Проверить доступность оценки комиссии. Зафиксировать проверенные имена, полные хеши схем и требования к токенам. Наличие имени в каталоге подтверждает обнаружение инструмента. Право выполнить операцию проверяется отдельно в Sandbox. В рабочем контуре используются только диагностика и проверки без торговых вызовов.

Для отправки применяется отдельный серверный список торговых инструментов Sandbox. Каждый вызов проверяет владельца, счёт, контур и совпадение схемы. Аналитический MCP-ассистент сохраняет доступ к чтению. Если поиск по исходному ключу или защита от дублей недоступны, отправка через MCP остаётся выключенной до согласования решения.

## Подтверждение и исполнение

1. Пользователь выбирает счёт, инструмент, направление и количество лотов. Предпросмотр показывает счёт, контур, инструмент, размер заявки, доступный остаток, ориентировочную сумму и комиссию при наличии данных.
2. Подтверждение привязано к владельцу, счёту, версии подключения и показанным параметрам. Изменение параметров требует нового предпросмотра. При отправке сервер проверяет доступность инструмента, деньги для покупки и незаблокированный остаток для продажи. Если данные существенно изменились или проверка недоступна, сервер запрашивает новый предпросмотр.
3. Перед вызовом MCP сервер сохраняет запись операции и ключ заявки. Повтор с тем же ключом и параметрами возвращает сохранённый результат. Повтор с изменёнными параметрами отклоняется.
4. При тайм-ауте или обрыве соединения сервер отмечает статус как неизвестный и сверяет исходную заявку по ключу. Повторное чтение статуса не отправляет заявку. Интерфейс показывает статус и исполненные лоты. При подтверждённом исполнении обновляются портфель и денежный остаток.

## Приёмка

- Проверить, что форма портфеля и текстовая команда приводят к одному предпросмотру. Уточнить неоднозначную бумагу или недостающее количество. Проверить редактирование, отмену и повторное подтверждение черновика.

- Проверить сохранение границ между владельцами, счетами и контурами, отказ при изменении схемы и недоступных правах.
- Проверить предпросмотр, подтверждение конкретных параметров, отклонение при недостаточном остатке и повторном использовании ключа с другими параметрами.
- На подставном MCP проверить отказ брокера, частичное исполнение, тайм-аут до получения биржевого ID и сверку по ключу после перезапуска. На один ключ допускается один вызов отправки.
- На собственном счёте Sandbox вручную купить и продать один лот через MCP со сверкой позиции и денежного остатка. В рабочем контуре проверить только каталог, схемы и доступ без выставления заявок.

## Текстовая команда и макет

В поле MCP-аналитики Sandbox пользователь может написать «Купи один лот SBER» или «Продай два лота SBER». Модель выделяет направление, бумагу и число лотов. Сервер проверяет параметры для выбранного счёта Sandbox и подготавливает черновик. При неоднозначной бумаге, неизвестном количестве или отсутствии выбранного счёта приложение запрашивает уточнение. Доступ модели ограничен подготовкой черновика. Брокерский вызов отправки делает сервер после явного подтверждения пользователя.

В ответе на команду показать действие «Проверить заявку», которое открывает ту же форму, что и покупка или продажа из портфеля. В форме видны Sandbox, счёт, способ отправки MCP, бумага, направление, лоты, доступный остаток и оценка расходов. Пользователь может изменить параметры с повторным предпросмотром, закрыть форму или подтвердить заявку.

[Интерактивный макет заявок](./design/mcp-sandbox-orders.html) согласован 13.11.2026. В портфеле один переключатель REST / MCP с исходным выбором REST. Текстовая команда с произвольным тикером и количеством лотов открывает предпросмотр через MCP. В общей форме синяя кнопка «Купить» и красная кнопка «Продать» выбирают направление. Отдельная кнопка подтверждает выбранное действие. Макет показывает уточнение команды, редактирование и отмену предпросмотра, а также сверку статуса на демонстрационных данных.
