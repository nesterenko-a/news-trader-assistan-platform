# 12. Дорожная карта развития

**Статус:** утверждено v1.24  
**Система:** NewsTrader Assistant

Этапы развития системы. Сроки ориентировочные и зависят от размера команды.

## Этап 0. Фундамент (MVP)

**Цель:** проверить ключевую гипотезу — система умеет давать обоснованный вердикт по бумаге.

**Фокус среза:** рынок Мосбиржи; сектора авиация + нефть (AFLT, LKOH, GAZP и связанные бумаги). Стек: Python + FastAPI + PostgreSQL, граф в таблицах, NLP через LLM API (DeepSeek → OpenAI).

| Задача | Результат | Статус |
|---|---|---|
| Конвейер сбора новостей: RSS российских агентств + Telegram-каналы | Работающий сбор, нормализация, дедупликация; автоматический запуск по расписанию | RSS ✅ / Telegram (источник) ✅ |
| NLP-анализ через LLM: тематика, тональность, сущности, факты | Структурированный анализ новостей (русский язык) | ✅ |
| Базовый knowledge graph: 50–100 сущностей и курируемых связей | Цепочки влияния по отраслям | ✅ (66 сущностей, 85 связей) |
| Биржевые данные через MOEX ISS + базовые индикаторы | Актуальные котировки и индикаторы по целевому списку | ✅ |
| Strategy Engine первой версии + обоснование | Вердикты BUY/SELL/HOLD/INSUFFICIENT_DATA | ✅ (калибровка проход 1) |
| REST API + минимальный веб-интерфейс + Telegram-бот | Запрос аналитики по тикеру тремя способами | ✅ / ✅ / ✅ |
| Инфраструктура: Docker (Postgres + Liquibase), планировщик | Воспроизводимое развёртывание и контроль схемы | ✅ |

**Критерий выхода:** пользователь получает обоснованный вердикт с цитатами и ссылками по интересующей бумаге; метрики качества NFR-04 достигнуты на валидационном наборе. Оценка качества накапливается через бэктест-харнесс ([13-operations.md](./13-operations.md)).

## Этап 1. Продуктовое ядро

**Цель:** полноценное пользовательское использование.

| Задача | Результат |
|---|---|
| Watchlist, портфель, история запросов | Полный цикл пользователя (UC-01…UC-05) |
| Алерты по значимым новостям | Уведомления по настройкам |
| Макрокалендарь и привязка к бумагам | Контекст событий в вердиктах |
| Расширение источников: Telegram, сайты компаний, английский язык | Шире охват, мультиязычность |
| **Бэкфилл исторических новостей:** RSS (глубина ограничена выдачей ленты — обычно дни/недели), архив и поиск Telegram-каналов (Telethon, глубокая история), архивы/поисковые API источников | Быстрый старт ассистента и исторические бэктесты на прошлых периодах |
| Обратная связь «сработало/не сработало» | Статистика качества в интерфейсе |
| Бэктестинг вердиктов «на момент T» | Отчёты о качестве за периоды |

**Статус:** начат. Реализованы срезы 1–6: авторизация (регистрация/вход/сессии), watchlist, портфель с переоценкой по MOEX и P&L, история стратегий, алерты по значимым новостям (генерация в конвейере, API и веб-страница с настройками), push-доставка алертов в Telegram (привязка чата по коду `/link`, доставка в конвейере), макрокалендарь (модель данных, API, веб-страница и блок на карточке бумаги, наполнение), обратная связь «сработало/частично/нейтрально/не сработало» (API, страница истории со статистикой качества, кнопки на карточке и при закрытии позиции), Telegram-источник новостей (Telethon, `--telegram` в сборе и конвейере), **бэктестинг вердиктов «на момент T»** (`scripts/backtest_asof.py`: реконструкция вердикта только по данным, доступным в T, отчёт о качестве за периоды; устранено заглядывание в будущее в движке стратегий). Остаётся в этапе 1: сайты компаний как источник, английский язык, глубокий бэкфилл исторических новостей.

**Ограничение бэкфилла новостей:** RSS-ленты отдают только последние элементы (глубина — обычно от нескольких дней до недель), поэтому «полная» историческая загрузка через RSS невозможна. Глубокая история (месяцы/годы) доступна через архивы Telegram-каналов и поисковые API источников. Уже сейчас для ускорения старта скрипты `collect_news` и `daily_pipeline` поддерживают окно сбора: `--days N` (последние N дней) и `--from YYYY-MM-DD` (с указанной даты), а `collect_news --entity <имя>` — точечный сбор новостей по конкретным сущностям/бумагам.

## Этап 2. Углубление аналитики

**Цель:** повышение точности и доверия.

| Задача | Результат |
|---|---|
| Paper trading и сравнение с бенчмарком | Прозрачность реальной применимости |
| Научные источники в обоснованиях | Автоматический поиск и проверка ссылок |
| Обучение весов факторов на обратной связи | Версии весов, A/B-сравнение |
| Контраргументы и риски в автоматическом режиме | Полные evidence-цепочки |
| Расширение графа: 500+ сущностей, авто-кандидаты связей | Глубже покрытие отраслей |
| Модули биржевых индикаторов (см. [19-market-indicators.md](./19-market-indicators.md)) | Отдельные вызываемые индикаторы: пакет `app/market/indicators/`, REST API `/api/indicators/*`, веб-страница; MACD и уровни поддержки/сопротивления закрывают невыполненные пункты P0 FR-04-02 |

**Статус этапа 2:** начат. **Paper trading реализован** (виртуальный портфель): виртуальный счёт, автоматические позиции по вердиктам BUY/SELL в ежедневном конвейере (вход = close дня вердикта, вариант А — без заглядывания в будущее), ручное закрытие и сброс, метрики (P&L, доходность, % прибыльных сделок, средний результат, максимальная просадка) и бенчмарк «купил всё и держишь»; API `/paper` и веб-страница `/paper`. **Контраргументы и риски реализованы** (FR-05-07): движок детерминированно формирует контраргументы (разнонаправленные сигналы, техсигналы RSI, ближайшие макрособытия) и риски (рыночные, событийные, отраслевые/корпоративные); при значимых контраргументах уверенность снижается; вывод в вебе, Telegram и API. **Обучение весов на обратной связи реализовано** (FR-06-05): версионируемые веса факторов (news/graph/counter_penalty), движок применяет текущую версию, калибровка по оценкам `scripts/calibrate_weights.py` создаёт новые версии (историчность, A/B-сравнение). **Биржевые индикаторы:** список из 12 индикаторов утверждён ([19-market-indicators.md](./19-market-indicators.md), v1.0). **Реализован OI** — первый индикатор: пакет `app/market/indicators/`, таблица `market_open_positions`, скрипт `update_oi.py` (`--ticker`/`--all` с полем дней, по умолчанию 30), API `/v1/indicators` (список, расчёт OI с сигналами «цена × OI», список всех фьючерсов `/futures`), админка (тикер-поле с подсказкой фьючерсов, поле «дней», чекбокс «--all» с блокировкой тикера, прогресс-бар «загружено из N · осталось»). Следующий шаг — веб-страница `/indicators` (см. UI-требования §6.1 документа 19), далее — остальные индикаторы. Осталось в этапе 2: научные источники в обоснованиях, расширение графа.

## Этап 4. Исследовательский горизонт

- Автоматическое открытие новых связей графа по корпусу статей с кураторским подтверждением.
- Модель «реакции рынка»: прогноз краткосрочного движения цены на событие.
- Транскрибация видео/подкастов.
- Персональная адаптация вердиктов под стиль и рисковый профиль пользователя.

## Критерии перехода между этапами

- Каждый этап завершается замером метрик NFR-04 и демонстрацией ключевых сценариев.
- Гейт на выходе из этапа: отсутствие критических дефектов, метрики качества не хуже целевых, документация актуальна.
