# 31. Управление фоновыми задачами администратором

**Статус:** утверждено v1.2
**Система:** NewsTrader Assistant

## 1. Назначение

Полное управление фоновыми задачами находится в `/admin`: там администратор запускает скрипты, настраивает их параметры, изучает журнал и останавливает активный запуск. Realtime-демон дополнительно управляется глобальной status-плашкой в шапке. Все пользователи видят состояние живого процесса, но изменить его может только администратор.

Страница `/settings` содержит только лаконичный якорный раздел «Администрирование», доступный в её боковой навигации для администратора. Это не отдельный маршрут и не дубль админки: в нём показываются только активные задачи с toggle остановки. Запуск задач, notices и история запусков остаются в `/admin`.

## 2. Сценарии

- Администратор включает realtime в шапке: система сохраняет `realtime_config.enabled=true` и запускает `realtime_updater`, если он не работает.
- Администратор выключает realtime в шапке: система без дополнительного подтверждения выставляет `enabled=false`, отправляет запущенному процессу штатное завершение и фиксирует остановку в журнале.
- Администратор открывает `/settings`, переходит по якорю «Администрирование» и видит только работающие задачи. Toggle каждой карточки останавливает соответствующий запуск.
- Остановка любой работающей задачи требует подтверждения. Уже сохранённая часть результата не откатывается; в журнале отражается `stopped` и причина.

## 3. Права и интерфейс

- Все управляющие POST-маршруты требуют роль `admin`; для авторизованного не-админа — 403, для гостя — редирект на `/login`.
- В выпадающем меню пользователя отдельной ссылки «Администрирование» нет; остаётся ссылка «Админ» на полный раздел `/admin`.
- В боковой навигации `/settings` якорь «Администрирование» видит только администратор.
- В шапке между «API» и «Внимание» выводится цветная плашка ON/OFF с текстом «Обновление включено/выключено». Она показывает OFF, если настройка включена, но живого демона нет. Для не-админа плашка не интерактивна.
- Админка `/admin` сохраняет детальные карточки, параметры и логи; её кнопки запуска становятся контекстными и показывают «Остановить» для активной задачи.

## 4. Жизненный цикл процесса

- Раннер хранит живой дочерний процесс только в памяти текущего приложения, по `ScriptRun.id`.
- При остановке процесс получает `terminate`; если он не завершился за 10 секунд — `kill`.
- Остановленный запуск получает `status="stopped"`, ненулевой `exit_code`, `stopped_by`, `stopped_at` и запись в `output`. Это не создаёт notice об ошибке.
- После перезапуска веб-приложения незавершённые задачи отмечаются как `failed`, поскольку процесс-идентификатор больше недоступен.
- Ограничение параллелизма сохраняется: один обычный скрипт и один демон. Запуск дубликата возвращает конфликт состояния.

## 5. Модель и маршруты

`script_runs` получает nullable-поля `stopped_by` (FK `users`) и `stopped_at`; допустимый статус расширяется значением `stopped`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/admin/scripts/{run_id}/stop` | Остановить конкретный работающий запуск |
| POST | `/admin/realtime/toggle` | Включить/выключить realtime и при включении запустить демон |

Все POST принимают безопасный `return_to` только для локального пути приложения: значение начинается с одного `/`, но не с `//`.

## 6. Проверки

- Unit: запуск и остановка процесса, корректный `stopped`-аудит, освобождение слота, запрет остановки завершённого запуска.
- E2E: видимость и права header-toggle, якорный админ-блок в настройках, отсутствие отдельной ссылки в выпадающем меню, остановка обычного скрипта и возврат кнопки к «Запустить».
- После изменения: compileall, pytest, smoke, Playwright.
