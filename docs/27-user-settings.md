# 27. Настройки пользователя — ТЗ и дизайн

**Статус:** частично реализовано v1.9 (проект MVP управления счетами песочницы)
**Система:** NewsTrader Assistant
**Приоритет:** P1, этап 2 дорожной карты
**Связанные документы:** [05-non-functional-requirements.md](./05-non-functional-requirements.md), [07-data-model.md](./07-data-model.md), [10-api-specification.md](./10-api-specification.md), [11-security-compliance.md](./11-security-compliance.md), [12-roadmap.md](./12-roadmap.md), [14-web-interface.md](./14-web-interface.md), [archive/26-favorites.md](./archive/26-favorites.md)

## 1. Назначение

`/settings` — приватный центр управления личными данными, списками пользователя и будущими коммерческими интеграциями. Войти в него можно из меню «⋮» в шапке: имя пользователя становится ссылкой **«Настройки пользователя»**.

Страница собирает то, что относится к конкретному пользователю, но не заменяет рабочие страницы анализа. Watchlist, Портфель и Виртуальный портфель остаются самостоятельными страницами, а в Настройках становятся разделом с быстрыми переходами и краткими показателями.

**Реализовано:** `/settings`, профиль с ФИО/отображаемым именем/аватаром, Избранное, переходы к Watchlist, ручному и виртуальному портфелям, алерты и Telegram; подключение Т-Инвестиций только для чтения описано в [14-web-interface.md](./14-web-interface.md). Подписка, безопасность и приватность пока представлены заглушками.

**Отложено:** хранение адреса до внедрения шифрования, платежи, торговые операции брокера, 2FA, управление сессиями, экспорт и удаление данных.

## 2. Принципы

- Все личные данные добровольны: для работы сервиса достаточно имени пользователя и пароля.
- Данные видит и меняет только их владелец; администратор не получает их в интерфейсе по умолчанию.
- Для незавершённых возможностей отображается честная заглушка **«В разработке»**, а не активная форма, которая создаёт ложные ожидания.
- Избранное остаётся независимым от Watchlist и доступно в настройках как личный список (см. [archive/26-favorites.md](./archive/26-favorites.md)).
- Токен Т-Инвестиций хранится зашифрованным в отдельной записи пользователя (см. [11-security-compliance.md](./11-security-compliance.md)); платёжные реквизиты не хранятся.

## 3. Информационная архитектура и макет

Страница `/settings` имеет боковую навигацию на широком экране и сегменты/аккордеон на мобильном. Первый экран — «Профиль».

| Раздел | Содержимое | Статус первого релиза |
|---|---|---|
| Профиль | Аватар, ФИО, адрес, отображаемое имя | Реализовать |
| Избранное | Таблица личных акций и фьючерсов, переход к бумаге, звезда для снятия отметки | Реализовано |
| Мои инвестиции | Карточки-ссылки Watchlist, Портфель, Виртуальный портфель; краткие счётчики | Реализовать как навигацию |
| Уведомления | Ссылка на существующие настройки алертов и статус Telegram | Реализовать как навигацию |
| Подписка | Текущий план, вариант ежемесячной/годовой подписки, ссылка на описание тарифов | Заглушка «В разработке» |
| Брокеры и торговля | Подключение Т-Инвестиций только для чтения; будущие заявки с TP/SL | Подключение и портфель реализованы; торговля — в разработке |
| Безопасность | Смена пароля, активные сессии, 2FA, история входов | Заглушка, кроме существующего выхода |
| Данные и приватность | Экспорт данных, удаление аккаунта, согласия | Заглушка «В разработке» |
| Администрирование | Только для роли admin: активные фоновые задачи и toggle остановки | Реализовано |

В выпадающем меню «⋮» остаются короткие ссылки «Настройки пользователя», «Новости», «История», «Top-5», «Админ» (если есть роль) и «Выйти». Ссылки Watchlist, Портфель и Виртуальный портфель переносятся в раздел «Мои инвестиции» Настроек. Для администратора боковая навигация дополнительно содержит якорь «Администрирование», но отдельного пункта в выпадающем меню нет.

## 4. Пользовательские сценарии

### UC-27-01. Открыть настройки

Авторизованный пользователь открывает «⋮», нажимает на свой никнейм/«Настройки пользователя» и переходит на `/settings`. Гость получает редирект на `/login`.

### UC-27-02. Заполнить профиль

Пользователь добавляет или меняет ФИО, адрес и аватар, видит предварительный просмотр и сохраняет форму. Независимо от заполненности полей доступ к анализу сохраняется.

### UC-27-03. Управлять избранным

В разделе «Избранное» пользователь видит только свои бумаги. Тикер открывает карточку анализа, а звезда рядом с ним снимает отметку без перезагрузки.

### UC-27-04. Перейти к инвестиционным спискам

В разделе «Мои инвестиции» пользователь открывает Watchlist, Портфель или Виртуальный портфель. На карточках видны счётчики: бумаг Watchlist, открытых позиций и виртуальных позиций.

### UC-27-05. Посмотреть подписку

Пользователь видит текущий уровень **Free** и две будущие опции Pro: ежемесячную и годовую. Кнопка ведёт на страницу/документацию «Тарифы — в разработке»; оплаты и подписки не создаются.

### UC-27-06. Подключить брокера в будущем

Пользователь открывает «Брокеры и торговля», вводит токен Т-Инвестиций с доступом только для чтения, выбирает счёт и открывает его портфель. Выставление ордеров остаётся будущим срезом.

## 6. Профиль и модель данных

Расширение `users` личными полями смешает учётную запись и защищаемый профиль. Поэтому создаётся отдельная таблица `user_profiles` (одна строка на пользователя).

| Поле | Тип | Назначение |
|---|---|---|
| `user_id` | INTEGER PK/FK → `users.id` | Владелец профиля |
| `full_name` | VARCHAR(200), nullable | ФИО |
| `address_encrypted` | TEXT, nullable | Адрес в шифрованном виде |
| `avatar_path` | VARCHAR(500), nullable | Внутренний путь к обработанному аватару |
| `display_name` | VARCHAR(100), nullable | Будущее публичное имя; пока в интерфейсе остаётся username |
| `created_at`, `updated_at` | TIMESTAMP WITH TIME ZONE | Аудит изменения |

В первом релизе ФИО и адрес не публикуются в API стратегий, логи и Telegram. Адрес хранится только после выбора механизма шифрования на уровне приложения; если он не согласован, поле остаётся визуальной заглушкой и не принимается сервером. Аватары хранятся вне git, с непредсказуемым именем файла; старый файл удаляется только после успешной записи нового.

Для Избранного используется таблица `user_favorites` (см. [архивное ТЗ](./archive/26-favorites.md)). Брокерские данные хранятся отдельно от ручного портфеля — см. [07-data-model.md](./07-data-model.md).

## 7. Подписка и монетизация — проектный макет

До подключения эквайринга пользователь имеет план **Free**. В макете отображаются, но не продаются:

| План | Период | Предлагаемая фиксированная цена | Будущее наполнение |
|---|---|---:|---|
| Free | бессрочно | 0 ₽ | Базовая аналитика и личные списки |
| Pro Месяц | 30 дней | 990 ₽/месяц | Расширенные лимиты анализа, уведомления, дополнительные инструменты |
| Pro Год | 365 дней | 9 900 ₽/год | То же, оплата за 10 месяцев вместо 12 |

Цены — **макет, не оферта и не платёжное предложение**. Карточки ведут на `/pricing` с надписью «Тарифы и оплата в разработке» и ссылкой на этот документ. Реальная монетизация потребует отдельного ТЗ: провайдер платежей, чеки/налоги, оферта, возвраты, webhooks, статусы подписок и права доступа.

## 8. Брокеры и будущие заявки

Будущая цель — подключение выбранного пользователем брокера и создание заявок BUY/SELL с количеством, ценой, Stop-loss и Take-profit на основе сценария. До отдельного ТЗ не реализуются ни форма токена, ни передача ордеров.

Обязательные условия будущего ТЗ:

- список поддерживаемых брокеров и официальный способ OAuth/API;
- защищённое хранение токенов, ротация и аудит доступа; для Т-Инвестиций токен шифруется в отдельной записи БД с привязкой к пользователю и ключом вне БД — см. [11-security-compliance.md](./11-security-compliance.md); открытые токены не сохраняются в профиле, логах или браузере;
- явное подтверждение каждого ордера, предпросмотр комиссии/риска, двухфакторное подтверждение;
- лимиты риска, журнал действий, отмена и обработка частичного исполнения;
- юридический дисклеймер и разграничение «аналитика»/«исполнение сделки».

В карточке доступно подключение Т-Инвестиций только для чтения; будущая торговля с Stop-loss/Take-profit обозначена как отдельная функция в разработке.

## 10. API и веб-маршруты

Проектируемые методы профиля требуют аутентификации:

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/v1/me/profile` | Профиль без чувствительного адреса в ответе по умолчанию |
| `PATCH` | `/v1/me/profile` | Изменить `full_name` и `display_name`; адрес добавляется только после утверждения шифрования |
| `POST` | `/v1/me/avatar` | Загрузить и обработать аватар |
| `DELETE` | `/v1/me/avatar` | Удалить аватар |
| `GET` | `/settings` | SSR-страница Настроек пользователя |
| `GET` | `/pricing` | Статическая заглушка тарифов «В разработке» |

API Избранного описан в [10-api-specification.md](./10-api-specification.md); там же описан API подключения Т-Инвестиций. Для платежей, 2FA, удаления аккаунта и торговых операций отдельный API пока не проектировался.

## 11. Тестирование и критерии приёмки

Unit:

- доступ к `/settings` и API только владельцу сессии;
- создание пустого профиля и изменение ФИО/отображаемого имени;
- проверка MIME, размера и обработки аватара; отсутствие EXIF;
- профиль другого пользователя не раскрывается;
- счётчики и ссылки раздела «Мои инвестиции»;
- заглушки подписки и платежей не создают финансовых операций;

E2E:

- клик по никнейму в «⋮» открывает Настройки;
- сохранение профиля и отображение аватара после обновления;
- Избранное, Watchlist и Виртуальный портфель доступны из нужных разделов;
- гость перенаправляется на вход;
- карточки Подписки, Безопасности и Приватности содержат статус «В разработке»; карточка брокера позволяет подключение только для чтения, без оплаты и ордеров.

Критерий выхода: выполнены FR-27, миграции Liquibase обратимо применимы, не попадают личные данные/секреты в логи, пройдены `compileall`, `pytest -q`, `npx playwright test`, smoke; обновлены docs 04/06/07/10/11/12/14/17.

## 13. MVP управления счетами песочницы — проект

**Статус среза:** проект, требуется согласование перед реализацией. Создание, пополнение и закрытие счетов пока не реализованы; существующее подключение остаётся только для чтения. Обоснование: пользователь уже может подключить Sandbox token, но при пустой песочнице вынужден создавать счёт внешними средствами. Новая страница завершает этот сценарий внутри приложения.

### 13.1. Интерфейс и сценарии

Рядом с полем токена в Настройках появляется кнопка-ссылка **«Управление песочницей»**, ведущая на `/broker/t-invest/sandbox`. Она не отправляет форму подключения и не переносит токен в URL, браузерное хранилище или другую форму. Переход доступен и до подключения: страница объясняет, что сначала нужно сохранить Sandbox token, и даёт ссылку обратно на Настройки с выбранным sandbox. При сохранённом рабочем подключении показывается тот же переход к смене контура; никакие операции со счетами рабочего контура не вызываются.

После подключения песочницы страница содержит:

- заголовок «Песочница Т‑Инвестиций» и заметную подпись «Тестовые счета и виртуальные средства»;
- форму «Создать счёт»: необязательное название до 100 символов и кнопку «Создать»;
- список счетов: название, маскированный номер, статус и доступные рубли; ошибка получения остатка показывается явно, без подстановки нуля;
- для каждого счёта поле суммы в рублях и кнопку «Пополнить»;
- отдельную кнопку закрытия счёта `✕` в POST-форме по стандарту действий проекта, с подписью/aria-label «Закрыть счёт» и подтверждением удаления тестового счёта, его позиций и истории у брокера;
- кнопки «Обновить счета», «Открыть портфель» и ссылку обратно на Настройки.

**UC-1:** при пустом списке пользователь создаёт первый тестовый счёт; список обновляется без повторного ввода токена. **UC-2:** пополняет выбранный счёт виртуальными рублями и видит подтверждённый брокером остаток. **UC-3:** после подтверждения закрывает счёт, который исчезает из списка; при закрытии выбранного портфельного счёта выбор очищается. **UC-4:** при ошибке сети видит причину и способ сверить состояние, а не сообщение об успехе.

### 13.2. Ограничения и обработка запросов

- Любой авторизованный пользователь управляет только своей сохранённой песочницей. Сервер проверяет владельца, environment=sandbox и принадлежность account_id актуальному списку счетов, а не доверяет форме. Переключение на рабочий контур блокирует все sandbox-действия (409); запросов к production-серверу нет.
- Используются только три изменяющих метода SandboxService: OpenSandboxAccount, SandboxPayIn, CloseSandboxAccount. У брокера запрос имени — строка; сумма — MoneyValue. Точные внешние поля и ответы остаются в [OpenAPI песочницы](./openapi/t-invest-sandbox.openapi.yaml).
- MVP поддерживает пополнение в RUB: положительная десятичная сумма с точностью до копейки; запятая нормализуется в точку, NaN, Infinity, экспоненциальная запись, ноль и отрицательные значения отклоняются. Decimal переводится в units/nano без float. Ограничения брокера возвращаются понятным сообщением; неподтверждённый результат не считается пополнением.
- Все изменения идут через POST с проверкой Origin/CSRF существующего приложения; GET страницы ничего не создаёт и не пополняет. Ответы содержат Cache-Control: no-store. После POST — перенаправление обратно на страницу; повторное открытие/обновление страницы не повторяет действие.
- Для изменяющих RPC отключаются существующие автоматические повторы `_call`. Каждое действие имеет сохранённый ключ операции; двойной клик и повтор с тем же ключом не отправляют новый RPC. Другой payload с тем же ключом отклоняется (409).
- Таймаут, разрыв соединения, 5xx или перезапуск после отправки означают «результат неизвестен». Автоповтора нет: предложить обновить список/баланс. Для нового явного действия нужен новый ключ. Гарантия exactly-once на стороне брокера не заявляется.
- Во время выполняющегося действия смена токена/контура, отключение и конкурирующие изменения этого подключения отклоняются (409). После известного результата блокировка снимается; зависшие pending после перезапуска помечаются unknown. Чтение расписания не блокируется.
- После подтверждённого действия локальные счета и снимки синхронизируются. При ошибке синхронизации успех внешнего действия сохраняется с отдельным предупреждением; RPC не повторяется. Пополнение инвалидирует старый снимок счёта; закрытие удаляет его локальный счёт и снимок, очищает выбор и время обновления, если счёт был выбран. При создании текущий выбор счёта не меняется.
- Заявки, сделки, обмен валют и торговые операции рабочего контура в MVP не входят. Новых .env-переменных и эксплуатационных скриптов не требуется.

### 13.3. Предлагаемые маршруты приложения

Таблица описывает только проект новых маршрутов; действующий контракт остаётся в [10](./10-api-specification.md). После реализации факты переносятся туда и в [14](./14-web-interface.md).

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/broker/t-invest/sandbox` | Страница, чтение актуального списка тестовых счетов и остатков |
| POST | `/broker/t-invest/sandbox/create` | Создать счёт: name, operation_key |
| POST | `/broker/t-invest/sandbox/pay-in` | Пополнить: account_id, amount, operation_key |
| POST | `/broker/t-invest/sandbox/close` | Закрыть: account_id, confirmed, operation_key |
| POST | `/broker/t-invest/sandbox/sync` | Обновить локальный список счетов после внешних изменений |
| GET | `/v1/brokers/t-invest/sandbox/accounts` | JSON списка счетов, остатков и результатов действий текущего пользователя |
| POST | `/v1/brokers/t-invest/sandbox/accounts` | JSON создания счёта |
| POST | `/v1/brokers/t-invest/sandbox/accounts/{account_id}/pay-in` | JSON пополнения |
| POST | `/v1/brokers/t-invest/sandbox/accounts/{account_id}/close` | JSON закрытия с обязательным confirmed=true |

В API операции требуют operation_key; состояние действия возвращается как pending/success/failed/unknown с безопасным сообщением. Ошибки: 401 без входа, 403 при неверном Origin, 404 для чужого/отсутствующего счёта, 409 для неподходящего контура или конфликта операции, 422 для неверных полей, 502/503 при недоступности брокера. Успех и unknown различаются в ответе явно; секреты и сырые ошибки заголовков не возвращаются.

### 13.4. Модель данных и аудит

Счета и снимки используют существующие BrokerConnection/BrokerAccount/BrokerPortfolioSnapshot. Для защиты от повторов нужна новая таблица `broker_sandbox_actions`: UUID операции, user_id, connection_id (nullable после отключения), версия подключения, уникальный `(user_id, operation_key)`, вид create/pay_in/close, хэш нормализованного запроса, account_id, безопасные поля name/amount/currency, статус pending/success/failed/unknown, время начала/окончания, безопасный код ошибки и подтверждённый результат без токена. Запись pending фиксируется до внешнего RPC; терминальная запись позволяет повторно показать результат без повторного вызова. Полный токен, заголовки Authorization и дампы HTTP не сохраняются.

Изменения модели сопровождаются новой миграцией Liquibase, включая уникальность и индексы. Существующий BrokerConnectionEvent также получает события sandbox_create/sandbox_pay_in/sandbox_close с результатом; детализация операции остаётся в новой таблице. Источник календаря и формат шифрования токена не меняются. Перед отправкой проверяется версия подключения; конкурентная смена не подменяет адрес или токен уже начатой операции.

### 13.5. Проверки и критерий выхода

Pytest проверяет выбор исключительно sandbox-адреса, три RPC и MoneyValue, изоляцию владельца/счёта, защиту рабочего контура, CSRF, повтор ключа, таймаут без автоповтора, восстановление pending и синхронизацию после успеха/ошибки. На PostgreSQL проверяются миграция, уникальность ключа операции и конкурентные действия.

Playwright: переход кнопкой рядом с токеном, состояние до подключения, пустая песочница, создание счёта, пополнение, отмена и подтверждение закрытия, очистка выбранного счёта, повтор/обновление страницы, ошибки, блокировка production и мобильный экран. Изменяющие внешние операции в тестах подменяются; живой пользовательский токен не используется автоматически.

Критерий выхода: три действия работают из отдельной страницы только для песочницы, список и портфель согласованы, повтор не создаёт вторую операцию, неизвестный результат обозначен, проверки pytest/compileall/smoke/Playwright/OpenAPI и миграции прошли. После реализации обновляются документы-дома и инструкции использования; пока это только проект для согласования.
