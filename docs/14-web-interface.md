# 14. Веб-интерфейс

**Статус:** утверждено v1.57  
**Система:** NewsTrader Assistant

Описание веб-интерфейса системы. Telegram-бот описан отдельно: [15-telegram-bot.md](./15-telegram-bot.md).

## 1. Общие сведения

- Технология: серверный рендер (Jinja2) + минимальный vanilla JS, без фронтенд-фреймворков.
- Тёмная тема, адаптивная вёрстка.
- Статические файлы: `/static/style.css`, `/static/app.js`.
- По умолчанию доступен по адресу `http://localhost:8000`.

## 2. Маршруты

| `GET /securities/{ticker}?range=7d` | Карточка с графиком за 7 дней |
| `GET /securities/{ticker}?range=1y` | Карточка с графиком истории за 1 год |
| `GET /securities/{ticker}?range=5y` | Карточка с графиком за 5 лет |

| `GET /history` | История стратегий с обратной связью и статистикой качества (требует входа) |

| `GET /indicators` | Индикаторы: вкладки из реестра — OI (графики OI+цена, ΔOI, сигналы «цена × OI»), Volume Profile (профиль, POC/VAH/VAL/HVN/LVN), EMA (пересечения cross_up/cross_down), MACD (MACD/signal/hist, сигналы пересечения и знака гистограммы) |
| `GET /news` | News Sources Manager: управление RSS-лентами (требует входа) — таблица лент со статусами ✓/✗, фильтр по категории, ручное добавление с проверкой, LLM-поиск кандидатов, галочки **«LLM-разбор»** и **«Обход антибота»** у каждой ленты (fallback-парсинг через LLM и headless-браузер при неудаче штатного парсинга), кнопки «Проверить» и «Вернуть стандартные ленты» (вкладки Telegram/Сайты — в планах) |

## 3. Главная страница

Блоки:
1. **Заголовок и описание** — назначение сервиса.
2. **Поиск** — поле «Тикер» + кнопка «Анализировать»; редирект на карточку бумаги. Неизвестный тикер → 404.
3. **Таблица «Поддерживаемые бумаги»**:
   - столбцы: Тикер, Название, Сектор, Рынок;
   - **переключатель «Акции / Фьючерсы / Все»** (3 положения, сегментный toggle над таблицей) — фильтр по типу бумаги; у фьючерсов в названии пометка «(фьючерс)»;
   - **фильтры встроены в заголовки столбцов** «Сектор» и «Рынок» (выпадающие списки, авто-применение при выборе, «Все» — сброс); сектор фьючерса берётся от базовой акции (связь по `assetcode`), поэтому фьючерсы отображаются и фильтруются в том же секторе, что и их акция (Авиаперевозки, Металлургия и т.д.);
   - счётчик количества бумаг под фильтром;
   - клик по тикеру открывает карточку бумаги.

## 4. Карточка бумаги

Блоки сверху вниз:

1. **Шапка**: тикер, название, сектор, рынок; справа — вердикт (цветной бейдж) и кнопка «Сделать скриншот».
2. **Параметры стратегии**: горизонт, уверенность, net score.
3. **Котировки**: текущая цена, максимум/минимум дня, объём.
4. **График «История цены»**: серверный SVG-график по сохранённым дневным свечам; переключатель диапазонов **1 день / 7 дней / 1 год / 5 лет / Всё**; подписи дат и диапазона цен. При одной свече отображается плоская линия.
5. **Профиль объёма (Volume Profile)**: горизонтальный профиль — распределение объёма торгов по ценовым уровням за период (ширина бара = объём на уровне). Подсвечены **POC** (контрольная точка — максимальный объём), **VAH/VAL** (границы Value Area ≈ 70% объёма, линии), HVN/LVN (узлы высокого/низкого объёма — плотность бара). **Селектор периода** (1M / 2M / 3M / 6M / 1Y) — пользователь выбирает, за какой период считать (по умолчанию 2M = 60 торговых дней).
6. **Фьючерсы на акцию** (только для бумаг с фьючерсами): таблица фьючерсов, базовым активом которых является бумага (связь по `assetcode`): код (SECID), название, дата экспирации и ссылка **«Открытый интерес (OI) →»** на страницу `/indicators?ticker=<SECID>`.
7. **Открытый интерес фьючерса** (если есть данные OI): график **OI + цена фьючерса** и столбцы **изменения OI, %** для ближайшего по экспирации фьючерса на акцию (как на странице `/indicators`) + кнопка «Полная страница OI →».
8. **Уровни**: Вход, Take-profit, Stop-loss — крупными цифрами (TP зелёный, SL красный).
9. **Обоснование** — краткая выжимка, почему такой вердикт.
10. **Контраргументы и риски** — аргументы против вердикта (разнонаправленные сигналы, техсигналы RSI, сигналы OI фьючерса, профиль объёма — цена вне Value Area, ближайшие макрособытия) и сгруппированные риски (рыночные, событийные, отраслевые/корпоративные). OI-риск дополнен **«Вердикт по индикатору»** (покупка/продажа/удержание) и знаком **«?»** с всплывающей подсказкой (как у «Порог ΔOI, %» на `/indicators`), объясняющей трактовку сигнала OI (см. [09-strategy-engine.md](./09-strategy-engine.md) §4.1).
11. **Сигналы** — таблица: сущность, тип (прямой / косвенный / **OI (фьючерс)** / **профиль объёма**), тональность, вес, цепочка влияния. Для акций с фьючерсами добавляется строка с сигналом открытого интереса ближайшего фьючерса (вес «—» — сигнал учитывается через риски/контраргументы и ослабление net_score, см. [09-strategy-engine.md](./09-strategy-engine.md) §4.1); для всех бумаг — строка профиля объёма с POC и Value Area.
12. **Новости** — лента статей, связанных с бумагой: заголовок-ссылка, источник, дата, упомянутые сущности с тональностью (цветные теги).

**Скриншот:** кнопка «Сделать скриншот» сохраняет всю страницу в PNG. Основной механизм — `html2canvas` (CDN); при его недоступности — встроенный fallback без внешних библиотек (`/static/app.js`).

## 5. Авторизация, Watchlist и Портфель

- **Авторизация:** сессия на cookie `nt_token` (httponly). Незащищённые страницы перенаправляют на `/login`.
- **Значок «Внимание» (!):** отображается в шапке слева от колокольчика алертов (левее троеточия ⋮) у авторизованных и рядом с «Войти» у неавторизованных. По клику открывается попап со списком сообщений. **Четыре состояния значка:** ошибок нет — серый «!» (контур); есть информационные — синий «!»; есть некритичные — янтарный «!»; есть критичные — красный залитый «!» с пульсацией. **Счётчик-бейдж** над значком показывает число активных уведомлений (как у колокольчика, максимум `99+`); цвет бейджа соответствует критичности: синий (info) / янтарный (warning) / красный (critical). **Значок, бейдж и попап обновляются автоматически** (опрос `GET /api/notices` каждые 10 секунд) — без перезагрузки страницы. Сообщения в попапе выделяются цветом и левой полосой (синие — info, янтарные — warning, красные — critical) с датой; слева от текста — значок проверки по `source` (🗄 БД · 🤖 ИИ · 📡 Telegram · 📈 MOEX · 📰 RSS · 💾 диск · ⏰ устаревание · ⚙️ скрипт). Данные — из `GET /api/notices` (модель `SystemNotice`, см. 07-data-model; ТЗ монитора — [18-health-monitor.md](./18-health-monitor.md)). Уведомления создаются автоматически: сбой скрипта из админки (критично), прерывание запусков перезапуском сервиса (критично), монитором здоровья (БД/LLM/MOEX — критично, Telegram/RSS/диск/устаревание новостей — некритично, долго не запускавшиеся периодические скрипты — информационно).
- **Автоподсказки тикера (реализовано):** во всех полях ввода тикера (Аналитика, Портфель, Watchlist, Индикаторы — EMA/MACD и Volume Profile) при вводе показывается выпадающий список бумаг (`datalist`), наполняемый из `/v1/securities` (акции и фьючерсы из БД, подпись — название бумаги). В **Аналитике** подсказки фильтруются по выбранному toggle «Акции / Фьючерсы / Все»: «Акции» — только акции, «Фьючерсы» — только фьючерсы, «Все» — весь список. На странице **Индикаторов** поле «Код фьючерса (SECID)» (OI) показывает в подсказке только фьючерсы (список из `/v1/indicators/futures`).
- **Навигация:** для всех — Аналитика, Календарь, API. **Авторизованному** пользователю в шапке показываются колокольчик алертов и лаконичное вертикальное троеточие (⋮) без кнопочного оформления. Колокольчик расположен слева от троеточия, ведёт на `/alerts` и показывает красный бейдж с числом непрочитанных алертов (максимум `99+`). Троеточие открывает компактный pop-up, выровненный по правому краю, с именем пользователя сверху и пунктами Watchlist, Портфель, Виртуальный портфель, История (и Админ для роли admin), Выйти. Pop-up закрывается по повторному клику, клику вне него или клавише Escape; неавторизованному доступна только ссылка «Войти». Автообновления страниц не перезагружают её целиком (например, живой лог запуска скрипта на `/admin/runs/{id}` подтягивается через AJAX), поэтому открытый pop-up меню не сбрасывается при обновлении данных.
- **Watchlist (`/watchlist`)**: форма добавления по тикеру, таблица бумаг с последним вердиктом и уверенностью, кнопка удаления.
- **Портфель (`/portfolio`)**: форма добавления позиции (тикер, количество, средняя цена входа), таблица позиций с текущей ценой MOEX, стоимостью, P&L (руб. и %), вердиктом; итоговая строка со стоимостью и P&L всего портфеля. Количество в колонке **«Кол-во»** выводится целым числом (без сотых: `9448.00` → `9448`); цены и стоимость — с копейками. Цвета: зелёный — прибыль, красный — убыток. **Закрытие позиции** — кнопка «Закрыть» открывает модальное окно с оценкой исхода: «Сработало / Нейтрально / Не сработало» (или «Отмена»); оценка привязывается к последней стратегии по бумаге и попадает в статистику качества.
- **Алерты (`/alerts`)**: список значимых новостей по бумагам watchlist с метками «новое» и «требует проверки»; кнопки «Прочитано», «Прочитать все»; форма настроек: порог значимости (0–1) и каналы (веб / Telegram); блок **Telegram-уведомления** — привязка чата по коду из бота (`/link`), отображение статуса и кнопка «Отключить Telegram».
- **История стратегий (`/history`)**: таблица сохранённых вердиктов (тикер, вердикт, горизонт, уверенность, дата, версия модели) с кнопками обратной связи **«Сработало / Частично / Не сработало»** (активная оценка подсвечена); вверху — статистика качества пользователя: счётчики и процент сработавших. Аналогичные кнопки доступны на карточке бумаги под вердиктом.
- **Виртуальный портфель (`/paper`)**: имитационная торговля по вердиктам на виртуальный капитал. Счёт (стартовый капитал), таблица открытых позиций с переоценкой по MOEX и P&L (₽ и %), история сделок с привязкой к вердиктам, метрики (доходность, % прибыльных сделок, средний результат, максимальная просадка) и график/сравнение с бенчмарком (IMOEX или «купил всё и держишь»). Количество в таблицах выводится целым числом (без сотых). Кнопка ручного закрытия позиции и сброса портфеля. Позиции открываются/закрываются автоматически в ежедневном конвейере по вердиктам.
- **Индикаторы (`/indicators`)**: общая страница для всех индикаторов. **Навигация строится автоматически из реестра** `app/market/indicators/registry.py` (вкладки-ссылки сверху): при добавлении нового индикатора в реестр он автоматически получает вкладку на странице (обязательное правило, см. [19-market-indicators.md](./19-market-indicators.md) §6.1). Сейчас доступны вкладки:
  - **Открытый интерес (OI)**: форма — код фьючерса с выпадающей подсказкой из списка всех фьючерсов MOEX, диапазон дат, порог ΔOI (у поля — значок «?» со всплывающей подсказкой: как выбрать порог). Результат: **график OI и цена** (две линии на общей шкале времени с **легендой**: OI — открытые позиции, цена — close; **оси**: по X — даты (5 меток «дд.мм»), по Y — значения OI (слева) и цены (справа, оранжевым)), **график изменения OI в %** (столбцы вокруг нулевой оси, зелёный/красный), **график «Объём торгов»**, **статья-справка «Как читать сигналы "цена × OI"»** (что такое OI и как он формируется, почему это важно, полная таблица трактовок «цена × OI» — Strong Bull / Strong Bear / Bearish Setup / Bullish Setup / Long Liquidation / Short Covering и комбинации без сигнала, «о чём помнить»: экспирация, резкие скачки цены, OI как дополнительный индикатор, структура участников на MOEX; какие индикаторы использовать для более достоверного прогноза; источник — статья Т-Банка «Когда покупать фьючерсы: открытый интерес») и **таблица сигналов** (отсортирована от новых к старым, свежие сверху; трактовки со стрелками направления цены и OI: ↑ — рост, ↓ — падение, → — без изменений, и пометкой объёма «· объём растёт ↑ / объём падает ↓» — подтверждение движения «новыми деньгами»; колонка **«Объём»**: значение объёма в день сигнала, изменение в % (зелёным/красным) и человеческая интерпретация «подтверждает движение» / «движение на излёте»; «Важность» у сигнала Strong Bear — открытие коротких позиций — выделена красным, у остальных сильных — зелёным, у предупреждений — жёлтым). **Блок «Нетто-позиции по группам клиентов»** (COT-визуализация, см. [19-market-indicators.md](./19-market-indicators.md) §8.14): двухпанельный график — сверху линия **цены** фьючерса, снизу **группированные столбцы нетто-позиций (long − short)** физиков (синие) и юриков (оранжевые) **вокруг нулевой оси** (выше нуля — перевес длинных, ниже — коротких; пересечение нуля — смена настроений группы; зеркальность — тождество OI); **таблица** «Открытые позиции по группам клиентов» (дата, физ/юр long/short/нетто, сумма, доля физиков %, спред «юр−физ», **Δ OI** — динамика открытых позиций группы день-к-дню: общая (long+short) и отдельно по длинным/коротким (`−` инертная <2%, `↑`/`↑↑`/`↑↑↑` рост 2–5/5–10/≥10%, `↓`/`↓↓`/`↓↓↓` падение; у заголовка — тултип-«?», точные % — при наведении на строку; зелёный — рост, красный — падение) с **сортировкой по клику** на заголовки Дата / Физ нетто / Юр нетто (▲/▼), **подсветкой** строк с противоположными ставками групп и **строкой «Итого»** с суммами по колонкам (кроме даты, спреда и Δ OI); фильтры дат ОТ/ДО — поля диапазона вкладки. Пропуски в ряду OI — разрывы линии.
  - **Профиль объёма (Volume Profile)**: форма — тикер (акция или фьючерс) и **период** (1M / 2M / 3M / 6M / 1Y, по умолчанию 2M). Результат: горизонтальный **профиль объёма** (бары объёма по ценовым уровням, POC подсвечен, линии VAH/VAL), легенда POC/VAH/VAL и **таблица сигналов** Volume Profile (POC, Value Area, HVN, LVN с трактовками).
  Ссылка в навигации «Индикаторы».
- **Администрирование (`/admin`)**: только для роли `admin`. Сетка карточек со скриптами проекта (ежедневный конвейер, сбор новостей, обновление цен, алерты, наполнение календаря/справочников, калибровка, бэктесты) — кнопка «Запустить» (+ числовой параметр там, где нужен); **«Обновить открытые позиции (OI)»** — текстовое поле «Код фьючерса» с выпадающей подсказкой из списка всех фьючерсов MOEX (заполняется из `GET /v1/indicators/futures`), поле **«За последние N дней»** (по умолчанию 30; применяется и к тикеру, и к режиму `--all`), **чекбокс «Скачать OI по всем фьючерсам (--all)»** — при установке поле тикера блокируется, и **селект «Шаблон фьючерсов»** — выбор сохранённого шаблона (см. ниже); при выборе шаблона его тикеры передаются в скрипт (`--tickers`, приоритетнее ручного тикера); таблица последних запусков со статусом; страница результата с **живым логом** и **прогресс-баром** «загружено из N · осталось» (по строкам `[i/N]` в логе): скрипты запускаются без буферизации вывода и сообщают о ходе работы в реальном времени (фазы конвейера, прогресс по тикерам, «ИИ-анализ» по каждой новости); вывод дозаписывается в БД по мере выполнения, страница авто-обновляется каждые 3 секунды; в конце — статус и код выхода. Одновременно выполняется один скрипт. Таймаут запуска — **свой на скрипт**: `SCRIPT_TIMEOUT_SECONDS_<KEY>` (например `SCRIPT_TIMEOUT_SECONDS_UPDATE_OI`), иначе дефолт скрипта (`Обновить открытые позиции (OI)`/`Скачать OI по всем фьючерсам` — 2 часа, остальные — 30 минут), иначе глобальный `SCRIPT_TIMEOUT_SECONDS` (по умолчанию 1800 с).
- **Макрокалендарь (`/macro`)**: таблица событий (заседания ЦБ, CPI/PMI/ВВП, сезоны отчётностей) с датой, регионом, значимостью и затронутыми бумагами. **Фильтры встроены в заголовки столбцов**: Регион, Значимость (высокая/средняя/низкая), Бумаги — «Весь рынок» (только рыночные события) / «Бумаги из: Watchlist» / «Бумаги из: Портфель» (только события, привязанные к бумагам из личного кабинета пользователя; рыночные события при этом не включаются). **Сортировка по дате** — клик по заголовку «Дата» переключает порядок (▲/▼). На карточке бумаги — блок «Макрособытия» с ближайшими событиями.

## 6. Запуск

**Шаблоны фьючерсов (для OI)**: именованные списки фьючерсов (SECID) для отслеживания OI. ТЗ интерфейса — §6.1. Выбранный в карточке «Обновить открытые позиции (OI)» шаблон передаётся в скрипт как `--tickers`. Модель `FuturesTemplate` (см. [07-data-model.md](./07-data-model.md)).

### 6.1. ТЗ: страница «Шаблоны фьючерсов»

**Статус:** утверждено (v1.52).

**Назначение.** Отдельная страница админки для создания, наполнения, редактирования и удаления шаблонов фьючерсов, за которыми ведётся наблюдение (OI). Шаблон — именованный список SECID; используется при запуске скрипта «Обновить открытые позиции (OI)» (селект в карточке, `--tickers`).

**Маршруты:**
- `GET /admin/futures-templates` — страница: список шаблонов + редактор состава (только admin);
- `POST /admin/futures-templates/save` — создание/обновление шаблона (поля: `id` (пусто — новый), `name`, `tickers` CSV);
- `POST /admin/futures-templates/delete` — удаление шаблона (`template_id`);
- старые `POST /admin/templates/add` и `/admin/templates/delete` остаются рабочими (совместимость), но карточка на `/admin` заменяется ссылкой «Шаблоны фьючерсов →» на новую страницу.

**Сценарии (UC):**
- UC-1 Создать шаблон: «Создать шаблон» → ввести название → «Загрузить фьючерсы» → выбрать бейджи → «Добавить выбранные» → «Сохранить шаблон».
- UC-2 Открыть/отредактировать: клик по шаблону в списке → его состав загружается в редактор (название + список тикеров); добавление/удаление бейджей; «Сохранить» (перезаписывает).
- UC-3 Удалить шаблон: «×» у строки списка (с подтверждением).
- UC-4 Запуск OI: на `/admin` в карточке «Обновить открытые позиции (OI)» селект «Шаблон фьючерсов» → запуск с `--tickers` из шаблона.

**Состав бейджа фьючерса** (данные из `GET /v1/indicators/futures`):
- **иконка отрасли** — круглый значок-подложка слева от тикера: спрайт из PNG-атласа `static/futures_icons.png` (1717×916, иконки 42×42; координаты по CSV-карте) — **все 21 отрасль** (авиаперевозки, автопром, банки, девелопмент, драгметаллы, металлургия, нефтегаз, ритейл, телеком, технологии, транспорт, уголь, химия, цветмет, электроэнергетика, индексы, валюты, товары, проценты, крипто, прочее); неизвестная — «?»;
- тикер `SECID` (например W4V6), серия `SHORTNAME` (WHEAT-10.26), рус. наименование `SECNAME`;
- **отрасль**: для фьючерсов на акции — сектор базового актива из справочника (`assetcode → securities.sector`, как в Аналитике); для неакционных — категория: Индексы / Валюты / Товары / Проценты / Крипто / Прочее; нет данных — «—»;
- **дата экспирации** `LASTDELDATE` (дд.мм.гггг);
- OI предыдущего дня `PREVOPENPOSITION` (формат: 1 234 567);
- объём лота `LOTVOLUME` (ед. базового актива);
- ГО `INITIALMARGIN` (₽), шаг цены `MINSTEP` / стоимость шага `STEPPRICE` (₽);
- расчётная цена `PREVSETTLEPRICE` (₽);
- **тип поставки: «—»** (заглушка; официального поля в ISS нет, эвристика не используется).

**Сетка и навигация:**
- кнопка «Загрузить фьючерсы» — разово подтягивает список из `/v1/indicators/futures` (кэш 1 ч) и рендерит бейджи;
- **20 бейджей на страницу** (сетка **4 колонки × 5 строк**), пагинация «← 1 2 3 … N →» (страницы по 20);
- **фильтры**: текстовый поиск (тикер/серия/наименование), отрасль (select), экспирация (до 1 мес / 1–3 мес / 3–6 мес / >6 мес), тип поставки (пока один вариант «—» — фильтр скрыт до появления данных);
- выбор бейджа — клик (подсветка рамкой, галочка); «Добавить выбранные» — перенос в **список наполнения** внизу (бейджи-мини с кнопкой ×); дубли исключаются.

**Список наполнения** — отображает текущий состав шаблона: бейджи-мини (тикер, серия, отрасль, дата экспирации) + «×»; количество; кнопки «Сохранить шаблон» / «Очистить список».

**Ограничения:** имя шаблона уникально (перезапись при совпадении); список тикеров хранится CSV в `FuturesTemplate.tickers`; пустой шаблон не сохраняется (ошибка валидации).

**Критерии приёмки:**
- страница доступна только admin; на `/admin` есть ссылка на неё;
- после «Загрузить фьючерсы» рендерится сетка ≤20 бейджей (4×5) с характеристиками, пагинация и фильтры работают;
- выбор бейджей и «Добавить выбранные» наполняют список (без дублей), «×» удаляет;
- сохранение создаёт/перезаписывает `FuturesTemplate`; повторное открытие шаблона восстанавливает состав; удаление работает;
- карточка OI на `/admin` отдаёт выбранный шаблон в `--tickers`;
- `pytest` зелёный; документация (14) обновлена.

Веб-интерфейс запускается вместе с Telegram-ботом единым лаунчером (`python -m scripts.run_app`, см. [13-operations.md](./13-operations.md)) или отдельно: `uvicorn app.main:app`.
