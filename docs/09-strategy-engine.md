# 09. Движок генерации стратегий

**Статус:** утверждено v1.5  
**Система:** NewsTrader Assistant

Документ описывает, как система превращает новости, знания о связях экономики и биржевые данные в обоснованный вердикт по ценной бумаге.

## 1. Входные данные

| Группа | Что входит |
|---|---|
| Новостные сигналы | Свежие обработанные новости по бумаге, отрасли, связанным сущностям (из [08-analysis-pipeline.md](./08-analysis-pipeline.md)) |
| Knowledge graph | Сущности, связи влияния, цепочки |
| Рыночные данные | Котировки, индикаторы (RSI, MACD, MA), волатильность, поддержка/сопротивление |
| Макрокалендарь | Ближайшие события и ожидаемый эффект |
| Контекст пользователя | Watchlist, портфель, горизонт интереса (если задан) |

## 2. Алгоритм работы

```
[1] Сбор сигналов по бумаге
        │
        ▼
[2] Построение цепочек влияния (граф)
        │  событие → сущность → … → целевая бумага
        ▼
[3] Оценка каждого сигнала (знак, сила, вес, затухание)
        │
        ▼
[4] Агрегация → сырой скор (net score)
        │
        ▼
[5] Сопоставление с индикаторами и макроконтекстом
        │
        ▼
[6] Формирование вердикта + уверенность + горизонт
        │
        ▼
[7] Сбор обоснования и контраргументов
        │
        ▼
[8] Ответ пользователю
```

### 2.1. Сбор сигналов

Выбираются новости за скользящий горизонт (по умолчанию 7 дней), затрагивающие:

- саму бумагу (прямые упоминания);
- отрасль бумаги;
- сущности, связанные с бумагой через граф (валюты, сырьё, макроиндикаторы, связанные сектора).

### 2.2. Построение цепочек влияния

Для каждой затронутой сущности движок находит пути до целевой бумаги по рёбрам `Influence`:

```
Пример: новость «Нефть выросла на 8%»
  Узел: нефть (commodity)
  Путь 1: нефть —(+strong)→ топливо —(−medium)→ авиакомпания
  Путь 2: нефть —(+strong)→ нефтегазовый сектор —(+strong)→ бумага(ЛУКОЙЛ)
```

Параметры пути:

- **суммарный знак**: произведение знаков рёбер (+ × − = −);
- **сила пути**: агрегация сил рёбер с затуханием по длине пути;
- **уверенность пути**: произведение уверенностей рёбер.

Ограничения обхода: максимальная длина пути (по умолчанию 3 ребра), отбрасывание путей с уверенностью ниже порога. Если путей нет — сигнал считается локальным (только для самой бумаги).

### 2.3. Оценка сигнала

Каждый сигнал получает значение:

```
signal = impact(news) × sign(path) × strength(path) × confidence(path)
```

где `impact(news)` — значимость новости с учётом временного затухания (см. 08).

### 2.4. Агрегация

- Сумма всех сигналов → **net score** по бумаге.
- Отдельно учитываются:
  - **согласованность** — насколько сигналы указывают в одну сторону (несколько разнонаправленных новостей → ниже уверенность);
  - **покрытие** — доля «свежего» влияния (если все сигналы старые → ниже уверенность);
  - **качество источников** — средний скоринг источников.

### 2.5. Сопоставление с рынком

Сырой скор корректируется рыночным контекстом:

| Ситуация | Эффект |
|---|---|
| Скор позитивный, RSI < 30 (перепроданность) | усиление сигнала к покупке |
| Скор позитивный, RSI > 70 (перекупленность) | сдерживание — риск коррекции |
| Цена пробила сопротивление / поддержку | подтверждение/опровержение тренда |
| Высокая волатильность | снижение уверенности, сокращение рекомендуемых горизонтов |
| Ближайшее макрособытие с high impact | пометка «ждать события» либо риск-фактор |

### 2.6. Вердикт и уверенность

- Пороговые правила: при `|net_score|` выше порога BUY/SELL, иначе HOLD.
- Пороги подбираются на исторических данных (бэктестинг, см. 09-12) и версионируются.
- **Уверенность**: комбинация величины скор, согласованности, покрытия, качества источников, близости к макрособытиям.
- Если объём данных слишком мал или уверенность моделей низкая — вердикт **INSUFFICIENT_DATA** (FR-05-05).

### 2.7. Горизонт

- Краткосрочный (дни): свежие новости, короткие цепочки влияния.
- Среднесрочный (недели–месяцы): отраслевые и макрофакторы.
- Долгосрочный (месяцы+): фундаментальные тренды, долгосрочные связи графа.

Горизонт выбирается по соотношению «свежесть сигналов ↔ длина и сила цепочек».

## 3. Обоснование (evidence chain)

Каждый вердикт сопровождается набором элементов обоснования (`EvidenceItem`):

| Тип | Пример |
|---|---|
| **news_fact** | «Нефть выросла на 8% за неделю» — цитата + ссылка |
| **graph_path** | «нефть → топливо → авиакомпании» с объяснением знака и силы |
| **indicator** | «RSI = 32 — бумага в зоне перепроданности» |
| **macro_event** | «19 числа заседание ЦБ, ожидаемое влияние — высокое» |
| **research** | Ссылка на научную/аналитическую работу, подтверждающую связь |
| **counterargument** | «Авиакомпания застраховала топливо на квартал — эффект может быть слабее» |

Каждому элементу присваивается вес — его вклад в вердикт. Это позволяет пользователю видеть, **что именно** повлияло на решение и насколько.

## 4. Контраргументы и риски

Движок детерминированно формирует контраргументы и риски для вердикта.

### 4.1. Контраргументы

- **Разнонаправленные сигналы**: для BUY — сигналы с отрицательным весом; для SELL — с положительным. Каждый оформляется как «<сущность>: усиливает/ослабляет (±вес)».
- **Техсигналы, противоречащие скору**: BUY при RSI > 70 (перекупленность), SELL при RSI < 30 (перепроданность) — берётся из индикаторной пометки.
- **Сигналы OI (открытый интерес, фьючерсы)**: противоречащие вердикту — BUY при `strong_bear`/`long_liquidation`, SELL при `strong_bull`/`short_covering` (см. [19-market-indicators.md](./19-market-indicators.md) §8.12). Дополнительно сигнал OI корректирует `net_score` (работает и в бэктесте «на момент T» — данные OI фильтруются по дате):
  - **противоречащий** вердикту сигнал ослабляет `net_score` на 15% (×0.85); если объём в день сигнала падает (`volume: "down"`) — ослабление слабее, ×0.92 (движение «на излёте»);
  - **согласный** с вердиктом сигнал при растущем объёме (`volume: "up"`) усиливает `net_score` на 5% (×1.05) — подтверждение «новыми деньгами».
  Для **акции** OI-сигнал берётся с **ближайшего по экспирации фьючерса** на эту акцию (связь по `assetcode`, см. [07-data-model.md](./07-data-model.md) §2.1); сигнал добавляется в «Сигналы» акции (kind `oi`, вес 0 — не влияет на net_score, только отображение) и участвует в рисках/контраргументах и корректировке наравне с OI-сигналом самого фьючерса.
- **Ближайшие макрособытия** высокого влияния (за 7 дней вперёд) — «ждать события».

### 4.2. Риски

Группируются по источникам:

- **рыночные** — индикаторные (перекупленность/перепроданность, сигналы OI);
- **событийные** — ближайшие высоко-значимые макрособытия;
- **отраслевые/корпоративные** — сигналы против вердикта по сущностям.

Если рисков нет — список пуст (не выдумываются).

### 4.3. Влияние на уверенность

Если суммарный вес контраргументов ≥ 30% от `|net_score|`, уверенность снижается на 15% (×0.85). Вердикт при этом не меняется (изменение на HOLD при большой доле контраргументов — на будущее).

### 4.4. Хранение и вывод

- Контраргументы сохраняются как `EvidenceItem(kind="counterargument")`.
- В ответе движка: `counterarguments: [{entity, text, weight}]`, `risks: [text]`.
- Отображаются на карточке бумаги (веб), в Telegram-ответе и в API (`StrategyResponse.counterarguments` / `risks`).

```
Вердикт:        ПОКУПКА
Горизонт:       среднесрочный (1–3 месяца)
Уверенность:    средняя (0.62)
Целевые уровни: вход ~1230, TP ~1420, SL ~1140 (справочно)

КЛЮЧЕВЫЕ ФАКТОРЫ
  [+] Рост нефти на 8% (ссылка) → нефтегазовый сектор → прямое влияние (+сильное)
  [+] Отчётность: выручка +14% г/г, EBITDA выше прогноза (ссылка)
  [−] RSI = 68 — близко к перекупленности

ЦЕПОЧКА ВЛИЯНИЯ
```

## 6. Версии и воспроизводимость

- Каждый вердикт хранит: версию моделей анализа, версию весов, версию графа, момент генерации.
- При изменении моделей старые вердикты не пересчитываются (историчность), но бэктестинг может прогнать их заново.
- Случайность исключается: те же входные данные → тот же вердикт.

### 6.1. Веса факторов и обучение на обратной связи

**Версионируемые веса факторов** (таблица `factor_weights`):

| Фактор | По умолчанию | Применение |
|---|---|---|
| `news` | 1.0 | Множитель веса прямых новостных сигналов (`news_fact`) |
| `graph` | 1.0 | Множитель веса косвенных сигналов по цепочкам графа (`graph_path`) |
| `counter_penalty` | 1.0 | Множитель снижения уверенности при значимых контраргументах |

- Каждая версия хранит: `version` (`w1`, `w2`, …), `factors` (JSON), `description`, `created_at`.
- Стратегия сохраняет `model_version` с суффиксом версии весов (например `mvp-0.1-w2`) — старые вердикты не пересчитываются, возможен A/B-сравнение версий.

**Пересчёт весов по обратной связи** (`scripts/calibrate_weights.py`):

- Использует накопленные оценки `UserFeedback` (worked / failed; `partial` и `neutral` в обучении не участвуют).
- Для каждой оценённой стратегии разбивает вклад evidence по типам (`news_fact` / `graph_path` / `counterargument`) и считает доли вклада (по модулю весов).
- Сравнивает средние доли в «сработало» vs «не сработало»:
  - доля косвенных сигналов (`graph`) в неудачных стратегиях выше, чем в удачных, на ≥ 10% → `graph` снижается на 10%;
  - доля прямых новостей (`news`) в удачных стратегиях выше, чем в неудачных, на ≥ 10% → `news` повышается на 10%;
  - ограничение: множители в диапазоне [0.5, 1.5].
- Создаёт **новую версию** весов (не перезаписывает текущую — историчность). Применяется к новым стратегиям; `counter_penalty` пока не обучается.
