## 12. МАШИННО-ЧИТАЕМЫЙ JSON-БЛОК (ОБЯЗАТЕЛЬНО)

В самом конце ответа, после раздела «11. Итоговая оценка», добавь отдельный блок строго в формате JSON между строками только с ```json и ``` . Никакого пояснительного текста внутри блока и после него.

Поля заполняй из того, что указал выше (итоговая оценка и Сценарии A/B/C из раздела «9. Моя стратегия»):

```json
{
  "verdict": "BUY | SELL | WAIT",
  "entry": "лучшая точка входа (диапазон или число)",
  "tp": "цели через /",
  "sl": "стоп",
  "scenario_a": {"title": "кратко", "entry": "", "stop": "", "targets": "", "why": "", "probability": "~65%"},
  "scenario_b": {"title": "кратко", "entry": "", "stop": "", "targets": "", "why": "", "probability": "~25%"},
  "scenario_c": {"title": "кратко", "entry": "", "stop": "", "targets": "", "why": "", "probability": "~10%"}
}
```

Правила:
- `verdict` — строго одно из `BUY` / `SELL` / `WAIT` (соответствует «Итоговой оценке»: 🟢 BUY, 🟡 WAIT, 🔴 SELL).
- `scenario_a` берётся из «Сценария A — основной» раздела «9. Моя стратегия» (или раздела «6. Основной сценарий»), `scenario_b` — из Сценария B, `scenario_c` — из Сценария C.
- `probability` каждого сценария — оценённая тобой вероятность реализации (в %), например `"~65%"`. Сумма вероятностей A+B+C не обязана быть 100 (сценарии не взаимоисключающие), но A (основной) должен иметь наибольшую вероятность.
- Если для какого-то сценария нет входа/стопа/целей (например, негативный сценарий «не покупать») — ставь пустую строку.
- Вложенные кавычки экранируй как \".
