# 17. Быстрый старт для новичка

**Статус:** утверждено v1.22 (документ сжат до пошагового маршрута; справочные таблицы команд и регламент — в [13-operations.md](./13-operations.md))
**Система:** NewsTrader Assistant

Пошаговое руководство, как впервые развернуть программу. Рассчитано на новичка, который впервые видит проект. Здесь — только «счастливый путь»; полный перечень скриптов, флагов, переменных `.env` и регламент запуска — в [13-operations.md](./13-operations.md) (единственный источник, сюда не копируется).

## 0. Что понадобится

- Windows (все команды ниже — из корня проекта, PowerShell или cmd).
- Python **3.13** (в виртуальном окружении проекта).
- **Docker Desktop** — для запуска PostgreSQL и миграций Liquibase.
- Интернет: MOEX ISS (цены), RSS-ленты и DeepSeek API (анализ новостей).
- Ключ **DeepSeek API** (`LLM_API_KEY`) — без него анализ новостей не работает, но цены и приложение запускаются.

## 1. Первый запуск (один раз)

### 1.1. Подготовить окружение

```
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
```

### 1.2. Настроить конфигурацию

Скопировать `.env.example` в `.env` и вписать свои значения (обязательно `LLM_API_KEY`; полный список переменных — [13-operations.md](./13-operations.md) §6):

```
copy .env.example .env
```

Все секреты живут только в `.env` — этот файл не попадает в git.

### 1.3. Поднять базу данных и применить миграции

```
docker compose -f docker/docker-compose.yml up -d db
docker compose -f docker/docker-compose.yml up --build migrations
```

Повторное применение миграций идемпотентно (Run: 0) — см. [13-operations.md](./13-operations.md) §2.

### 1.4. Установить зависимости E2E-тестов (первый раз)

E2E-тесты используют Playwright Test Runner (`tests/e2e/`), зависимости в git не коммитятся, поэтому на новой машине один раз:

```
npm install
npx playwright install chromium
```

Подробности окружения и стенда — [21-web-e2e-tests.md](./21-web-e2e-tests.md).

### 1.5. Наполнить справочники

```
.venv\Scripts\python.exe -m scripts.seed_db
```

Скрипт идемпотентен — можно перезапускать без вреда.

### 1.6. Проверить установку (опционально)

```
.venv\Scripts\python.exe -m scripts.smoke
```

## 2. Наполнение данными

### 2.1. Полная история цен (один раз)

```
.venv\Scripts\python.exe -m scripts.update_prices --from 2012-01-01
```

### 2.2. Ежедневный конвейер (каждый рабочий день)

```
.venv\Scripts\python.exe -m scripts.daily_pipeline
```

Конвейер собирает новости, догружает свечи, генерирует стратегии и алерты и торгует виртуальным портфелем. Состав фаз, повтор с фазы (`--from-phase`), окна сбора (`--days`/`--from`), Telegram- и сайты-источники (`--telegram`/`--sites`) — [13-operations.md](./13-operations.md) §3 и §5.

⚠️ Первый/повторный запуск идёт **долго** — анализ каждой новости через LLM занимает до двух минут. Это нормально. Прогресс — в `logs/pipeline.log`. Если ключа `LLM_API_KEY` нет, конвейер на шаге новостей упадёт с ошибкой авторизации — в этом случае обновляйте только цены:

```
.venv\Scripts\python.exe -m scripts.update_prices --days 5
```

После накопления новостей администратор может открыть `/admin/graph/candidates` и проверить автоматически найденные связи; до ручного принятия они не влияют на стратегии.

## 3. Запуск приложения

Веб-интерфейс + Telegram-бот поднимаются одним процессом:

```
.venv\Scripts\python.exe -m scripts.run_app
```

- Веб: http://localhost:8000
- Лог: `logs/app.log`
- Если `TELEGRAM_BOT_TOKEN` пуст — запустится только веб-интерфейс (с предупреждением).

Бот понимает команды `/start`, `/help` и просто тикер (AFLT, SBER, LKOH…) — см. [15-telegram-bot.md](./15-telegram-bot.md).

Дополнительные возможности (как включить — в [13-operations.md](./13-operations.md) §3.1–3.3):

- **«Теханализ в LLM»** — кнопка на карточке бумаги `/securities/{ticker}`;
- **«Top-5: лучшая сделка из шаблона акций»** — страница `/top5`;
- **«Реальное время»** — живые котировки по SSE: настройка и запуск демона через `/admin`.

## 4. Минимальный рабочий цикл новичка

1. Один раз: шаги 1.1–1.5 + `update_prices --from 2012-01-01` + бэкфилл новостей (`collect_news --from YYYY-MM-DD`, см. [13-operations.md](./13-operations.md) §5).
2. Каждое утро (или по расписанию): `daily_pipeline`.
3. Держать запущенным: `run_app`.
4. Полный регламент «что и когда запускать» (калибровка, бэктест, e2e и т.д.) — таблица в [13-operations.md](./13-operations.md).

Если у вас роль администратора, те же скрипты можно запускать из веб-интерфейса `/admin` с живым логом (см. [13-operations.md](./13-operations.md) §5 и [14-web-interface.md](./14-web-interface.md)).

## 5. Где смотреть результат

- **Веб** http://localhost:8000 — список бумаг, карточка с вердиктом, сигналами, новостями и графиком цены; виртуальный портфель на странице `/paper`.
- **Логи** в `logs/`: `pipeline.log` — конвейер; `app.log` — веб и бот.
- **БД** — данные в PostgreSQL (`newstrader`): `articles`, `market_candles`, `strategies`, `evidence_items`.

## 6. Типичные проблемы

| Проблема | Причина | Решение |
|---|---|---|
| Конвейер падает на новостях (401) | Пустой `LLM_API_KEY` | Вписать ключ в `.env`, либо обновлять только цены (`update_prices`) |
| Веб недоступен на 8000 | Порт занят | Проверить `logs/app.log`, сменить порт через `APP_URL`/uvicorn |
| БД не подключается | Контейнер не запущен | `docker compose -f docker/docker-compose.yml up -d db` |
| Миграции «не меняются» | Применялись ранее | Это нормально — применение идемпотентно (Run: 0) |
| Стратегий «мало» | Мало новостей/данных | Накопление — вопрос дней; вердикты `INSUFFICIENT_DATA` корректно отсекаются |
| Первый запуск «висит» | LLM-анализ идёт долго | Подождать; прогресс в `logs/pipeline.log` |
