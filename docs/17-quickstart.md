# 17. Быстрый старт для новичка

**Статус:** утверждено v1.2  
**Система:** NewsTrader Assistant

Пошаговое руководство, как впервые развернуть программу, какие скрипты запускать, какими командами и как часто это делать. Рассчитано на новичка, который впервые видит проект.

## 0. Что понадобится

- Windows (все команды ниже — из корня проекта, PowerShell или cmd).
- Python **3.13** (в виртуальном окружении проекта).
- **Docker Desktop** — для запуска PostgreSQL и миграций Liquibase.
- Интернет: MOEX ISS (цены), RSS-ленты и DeepSeek API (анализ новостей).
- Ключ **DeepSeek API** (`LLM_API_KEY`) — без него анализ новостей не работает, но цены и приложение запускаются.

## 1. Первый запуск (один раз)

### 1.1. Подготовить окружение

Создать виртуальное окружение и установить зависимости:

```
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
```

### 1.2. Настроить конфигурацию

Скопировать `.env.example` в `.env` и вписать свои значения (обязательно `LLM_API_KEY`):

```
copy .env.example .env
```

Все секреты живут только в `.env` — этот файл не попадает в git.

### 1.3. Поднять базу данных и применить миграции

```
docker compose -f docker/docker-compose.yml up -d db
docker compose -f docker/docker-compose.yml up migrations
```

Второй запуск миграций ничего не меняет (идемпотентно), поэтому её можно повторять после каждого обновления схемы.

### 1.4. Наполнить справочники

Бумаги, сущности и связи knowledge graph (это база, без неё ничего не работает):

```
.venv\Scripts\python.exe -m scripts.seed_db
```

Скрипт идемпотентен — можно перезапускать без вреда.

### 1.5. Проверить установку (опционально)

Смоук-тест API и веб-интерфейса (использует временную SQLite, ничего не портит):

```
.venv\Scripts\python.exe -m scripts.smoke
```

## 2. Наполнение данными

### 2.1. Полная история цен (один раз)

Скачать историю дневных свечей по всем бумагам из MOEX ISS с 2012 года (долго, но нужно только однажды):

```
.venv\Scripts\python.exe -m scripts.update_prices --from 2012-01-01
```

### 2.2. Ежедневный конвейер (каждый рабочий день)

Собирает свежие новости (RSS), анализирует их через LLM, догружает свечи и генерирует стратегии по всем бумагам:

```
.venv\Scripts\python.exe -m scripts.daily_pipeline
```

⚠️ Первый/повторный запуск идёт **долго** — анализ каждой новости через DeepSeek занимает до двух минут, весь прогон может занять десятки минут. Это нормально. Прогресс по стратегиям виден в `logs/pipeline.log`.

Если ключа `LLM_API_KEY` нет, конвейер на шаге новостей упадёт с ошибкой авторизации. В этом случае можно обновлять только цены (см. 2.3).

### 2.2a. Бэкфилл прошлых новостей (для старта и бэктестов)

Конвейер и `collect_news` умеют собирать новости за заданный период — полезно сразу наполнить базу историей для бэктестов:

```
.venv\Scripts\python.exe -m scripts.collect_news --days 14
.venv\Scripts\python.exe -m scripts.collect_news --from 2026-01-01
```

- `--days N` — только новости за последние N дней.
- `--from YYYY-MM-DD` — новости с указанной даты (приоритетнее `--days`).

Те же флаги принимает `daily_pipeline`, если нужно «новости за период + цены + стратегии» одним запуском:

```
.venv\Scripts\python.exe -m scripts.daily_pipeline --days 7
```

⚠️ Глубина бэкфилла по RSS ограничена выдачей лент (обычно от нескольких дней до недель) — «старые» новости сверх этого в RSS недоступны. Глубокая история планируется через Telegram-каналы и архивы источников (см. `12-roadmap.md`).

**Точечный сбор по бумаге/сущности** — когда нужны новости по конкретной компании, не дожидаясь общего конвейера (полезно после чистки данных):

```
.venv\Scripts\python.exe -m scripts.collect_news --entity Аэрофлот --days 30
.venv\Scripts\python.exe -m scripts.collect_news --entity Нефть --entity Газпром --days 14
```

Флаг `--entity` повторяемый, анализируются только статьи, упоминающие заданные сущности графа. Имя сущности должно совпадать с именем в графе (например, «Аэрофлот»).

### 2.3. Обновить только цены (по необходимости)

Быстрый способ, не требует LLM-ключа:

```
.venv\Scripts\python.exe -m scripts.update_prices --days 5
```

`--days N` — за сколько календарных дней взять свечи (на выходные/праздники удобно брать с запасом).

## 3. Запуск приложения

Веб-интерфейс + Telegram-бот поднимаются одним процессом:

```
.venv\Scripts\python.exe -m scripts.run_app
```

- Веб: http://localhost:8000
- Лог: `logs/app.log`
- Если `TELEGRAM_BOT_TOKEN` пуст — запустится только веб-интерфейс (с предупреждением).

Бот понимает команды `/start`, `/help` и просто тикер (AFLT, SBER, LKOH…).

## 4. Регламент: что и когда запускать

| Действие | Команда | Когда |
|---|---|---|
| Создать окружение, установить зависимости | см. 1.1 | один раз |
| Запустить БД | `docker compose -f docker/docker-compose.yml up -d db` | один раз (БД поднимается при старте Docker) |
| Применить миграции | `docker compose -f docker/docker-compose.yml up migrations` | один раз + после появления новых миграций |
| Наполнить справочники | `.venv\Scripts\python.exe -m scripts.seed_db` | один раз (идемпотентно) |
| Полная история цен | `.venv\Scripts\python.exe -m scripts.update_prices --from 2012-01-01` | один раз при старте |
| Бэкфилл новостей за период | `.venv\Scripts\python.exe -m scripts.collect_news --from YYYY-MM-DD` (или `--days N`) | один раз при старте (глубина ограничена выдачей RSS) |
| Ежедневный конвейер | `.venv\Scripts\python.exe -m scripts.daily_pipeline` | **ежедневно** в 09:00 (вручную или планировщик) |
| Обновить цены | `.venv\Scripts\python.exe -m scripts.update_prices --days 5` | ежедневно, если конвейер не запускается (например, нет LLM-ключа) |
| Запуск приложения | `.venv\Scripts\python.exe -m scripts.run_app` | постоянно (веб + бот) |
| Калибровка порогов | `.venv\Scripts\python.exe -m scripts.calibrate` | **раз в неделю** (после накопления новостей) |
| Бэктест качества | `.venv\Scripts\python.exe -m scripts.backtest` | **раз в 1–2 недели**, когда накопились вердикты старше 5 торговых дней |
| Смоук-проверка | `.venv\Scripts\python.exe -m scripts.smoke` | после изменений в API/веб-интерфейсе |

**Минимальный рабочий цикл новичка:**
1. Один раз: 1.1–1.4 + `update_prices --from 2012-01-01` + `collect_news --from YYYY-MM-DD` (бэкфилл новостей).
2. Каждое утро (или по расписанию): `daily_pipeline`.
3. Держать запущенным: `run_app`.

## 5. Где смотреть результат

- **Веб** http://localhost:8000 — список бумаг, карточка с вердиктом, сигналами, новостями и графиком цены.
- **Логи** в `logs/`:
  - `pipeline.log` — результаты конвейера (новости, свечи, по каждой бумаге: `STORED`/`REJECTED`);
  - `app.log` — работа веб-интерфейса и бота.
- **БД** — данные в PostgreSQL (`newstrader`): `articles`, `market_candles`, `strategies`, `evidence_items`.

## 6. Типичные проблемы

| Проблема | Причина | Решение |
|---|---|---|
| Конвейер падает на новостях (401/401) | Пустой `LLM_API_KEY` | Вписать ключ в `.env`, либо обновлять только цены (`update_prices`) |
| Веб недоступен на 8000 | Порт занят | Проверить `logs/app.log`, сменить порт через `APP_URL`/uvicorn |
| БД не подключается | Контейнер не запущен | `docker compose -f docker/docker-compose.yml up -d db` |
| Миграции «не меняются» | Применялись ранее | Это нормально — применение идемпотентно (Run: 0) |
| Стратегий «мало» | Мало новостей/данных | Накопление — вопрос дней; вердикты `INSUFFICIENT_DATA` корректно отсекаются |
| Первый запуск «висит» | LLM-анализ идёт долго | Подождать; прогресс в `logs/pipeline.log` |
