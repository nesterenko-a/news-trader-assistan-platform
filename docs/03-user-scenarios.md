# 03. Сценарии использования

**Статус:** утверждено v1.0  
**Система:** NewsTrader Assistant

Сценарии описывают, как пользователи взаимодействуют с системой. Формат — расширенные use cases с основным и альтернативными потоками.

## UC-01. Запрос аналитики по конкретной бумаге

**Актёр:** Пользователь  
**Предусловия:** система доступна, источники данных обновлены

**Основной поток:**
1. Пользователь запрашивает аналитику: «Что с акциями Аэрофлота?» или указывает тикер `AFLT`.
2. Система находит бумагу и проверяет доступность данных.
3. Система собирает свежие новости по бумаге, отрасли и связанным сущностям.
4. Система строит цепочки влияния по knowledge graph.
5. Система подтягивает биржевые индикаторы.
6. Система формирует вердикт ПОКУПКА / ПРОДАЖА / УДЕРЖАНИЕ с уверенностью и горизонтом.
7. Система формирует обоснование: цепочки влияния, цитаты, ссылки, контраргументы.
8. Пользователь получает структурированный ответ.

**Постусловия:** пользователь видит вердикт, обоснование, индикаторы и риски.

**Альтернативные потоки:**
- **3a.** Данных недостаточно (мало новостей): система сообщает «недостаточно информации для уверенного вердикта» и показывает то, что нашла.
- **3b.** Бумага не найдена по тикеру: система предлагает похожие варианты для уточнения.
- **7a.** Вердикт неуверенный: система явно помечает ограничения и предлагает следить за катализаторами (макрособытия, отчётность).

## UC-02. Просмотр ленты новостей по бумаге

**Актёр:** Пользователь

**Основной поток:**
1. Пользователь открывает карточку бумаги.
2. Система показывает хронологию новостей с пометками: сущности, тональность, значимость, влияние на бумагу.
3. Пользователь фильтрует ленту по дате, значимости, тональности, источнику.

**Постусловия:** пользователь видит контекст, на основе которого сформирована аналитика.

## UC-03. Настройка watchlist и портфеля

**Актёр:** Пользователь

**Основной поток:**
1. Пользователь добавляет бумаги в watchlist.
2. Пользователь вносит свои позиции: тикер, количество, среднюю цену входа.
3. Система показывает сводку по портфелю: текущие вердикты по каждой бумаге, суммарную экспозицию, самые значимые события недели.
4. Пользователь удаляет или редактирует позиции.

**Постусловия:** система отслеживает бумаги пользователя и использует их в аналитике.

## UC-04. Получение алертов

**Актёр:** Пользователь

**Предусловия:** у пользователя есть watchlist, алерты включены.

**Основной поток:**
1. Система обнаруживает новость высокой значимости по отслеживаемой бумаге.
2. Система формирует алерт: суть новости, ожидаемое влияние, ссылка.
3. Пользователь получает уведомление (в интерфейсе и/или через настроенный канал).

**Альтернативный поток:**
- **1a.** Новость значима, но неоднозначна: алерт с пометкой «требует ручной проверки».

## UC-05. Оценка качества рекомендаций (обратная связь)

**Актёр:** Пользователь

**Основной поток:**
1. Пользователь видит в истории вердикт по бумаге и его исход (цена выросла/упала/в диапазоне).
2. Пользователь ставит оценку: «сработало / частично / не сработало».
3. Система сохраняет оценку и использует её для пересчёта весов факторов.

**Постусловия:** система накапливает статистику качества.

## UC-06. Проверка стратегии на истории (бэктестинг)

**Актёр:** Пользователь, Аналитик

**Основной поток:**
1. Пользователь выбирает бумагу и период.
2. Система воспроизводит состояние «на момент T»: какие новости были, что знала система.
3. Система показывает, какой вердикт она бы выдала, и сравнивает с фактическим движением цены.
4. Пользователь видит отчёт: точность вердиктов, средний результат.

**Постусловия:** пользователь понимает, насколько системе можно доверять.

## UC-07. Paper trading (имитационный портфель)

**Актёр:** Пользователь

**Основной поток:**
1. Пользователь создаёт виртуальный портфель с виртуальным капиталом.
2. Пользователь открывает позиции по вердиктам системы.
3. Система ежедневно переоценивает портфель и показывает P&L.
4. Пользователь закрывает позиции.

**Постусловия:** пользователь накапливает статистику реальной применимости стратегий без риска.

## UC-08. Администрирование источников

**Актёр:** Администратор

**Основной поток:**
1. Администратор добавляет/отключает источники данных.
2. Администратор настраивает скоринг источников и правила приоритизации.
3. Администратор видит статистику сбора: количество новостей, ошибки коннекторов.

**Постусловия:** набор источников и правила сбора актуальны.

## UC-09. Работа с API

**Актёр:** Разработчик / сторонняя система

**Основной поток:**
1. Разработчик авторизуется через API-ключ.
2. Разработчик запрашивает аналитику, ленту новостей, индикаторы.
3. Разработчик получает данные в машиночитаемом формате.

**Постусловия:** внешние системы используют функциональность NewsTrader Assistant.
