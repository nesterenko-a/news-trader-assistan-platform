# Ручные заявки через MCP Т‑Инвестиций в Sandbox

**Этап:** постановка согласована.

## Цель и контекст

Проверить полный цикл ручной покупки и продажи рублёвых акций через MCP на одном счёте Sandbox. Аналитический пилот MCP использует инструменты чтения, а действующая форма торговли в Sandbox отправляет заявки через REST. Проверенный цикл отправки и сверки через MCP нужен для следующего этапа управления портфелем. [Дорожная карта](../docs/12-roadmap.md#торговля-и-управление-портфелем-через-mcp-тинвестиций).

## Границы

Первый срез охватывает ручную покупку и продажу рублёвых акций на одном счёте Sandbox. Проверка рабочего контура ограничена проверкой инструментов, схем и прав без торговых вызовов. Ребалансировка, наблюдение Top‑5 и допуск к реальной торговле идут отдельными этапами.

## Критерии готовности

1. Проверены доступные инструменты MCP, их схемы и права токенов в Sandbox и рабочем контуре. Торговые вызовы первого среза выполняются только в Sandbox.
2. Перед покупкой или продажей пользователь видит счёт, бумагу, направление, количество лотов, доступный остаток и оценку расходов. Сервер отправляет конкретную заявку после явного подтверждения.
3. Пользователь видит статус и количество исполненных лотов. После тайм-аута сервер сверяет исходную заявку по её ключу. Повторное подтверждение не создаёт дубль.
4. В Sandbox вручную пройдены покупка и продажа одного лота со сверкой позиции и денежного остатка. Автотесты покрывают отказ брокера, неопределённый статус и повторное подтверждение.
